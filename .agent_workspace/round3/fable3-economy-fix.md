## 4. 扫荡规则(SWEEP_RULES 精确语义 + core 动词)

balance.js 现有 `SWEEP_RULES` 字面量保留,语义固定如下(此前无实现,核心层缺动词):

```js
export const SWEEP_RULES = Object.freeze({
  unlock: 'firstClear',         // 该关已通(stars ≥ 1)即可扫;无星级要求
  freeDaily: 2,                 // 每日前 2 次扫荡免体力(全关卡共享额度,计入 campaign.daily.sweep)
  staminaCost: 'same-as-stage', // 免费额度外,消耗 = 该关 staminaCost(3/6)
  instant: true,                // 无战斗、无失败,立即结算
  rewards: 'repeat-once',       // 发放恰好一次该关 repeat 掉落 roll;不发 firstClear、不给星、不推进度
});
```

**core 需新增编排动词 `sweepStage(stageId)`**(opus-1,签名与 `challengeStage` 对齐):

1. 校验 `state.campaign.stars[stageId] ≥ 1`,否则 `{ ok:false, error:'该关未通关' }`;
2. `campaign.daily.sweep < freeDaily` 则免费,否则 `spend({ stamina: stage.staminaCost })`,不足报错;
3. 按 `stage.dropTable` roll 一次 repeat 掉落并入账(与胜利结算共用同一函数,杜绝两套掉落代码);
4. `campaign.daily.sweep += 1`;返回 `{ ok:true, rewards, free }`。

**设计角色**:扫荡是"体力→资源"的确定性转换阀。§3 的 58 点重试预算,卡关时的正确用法是扫荡换铜钱/秘银去强化,而不是反复送死(50 种子实测 p50 扫荡 4 次;策略缺它时 4/50 达标,有它 + 重试纪律后 27/50)。UI 侧(opus-4)在已通关卡上露出「扫荡」按钮即可,首通引导文案指向它。

## 6. 配套裁定 A(阻塞达标):1–20 关波次重锚(opus-2 · stages.js)

**问题**:stages.js 用自造曲线(120 → 30000 指数插值、精英 ×1.35)生成 `recommendPower` 与波次面板,R2 §D 的"敌方战力按表"未执行。实测该曲线第 10 关精英 = 校准值的 **2.34 倍**:玩家 533 战力打 579 锚点(比值 0.92)16 连败,曲线在校准外。

**裁定**:第 1–20 关(21–40 关见文末)`recommendPower` 与波次生成入参改为:

```
anchor(n) = round( STAGE_BALANCE[n].enemyPower × (isElite ? 1.3 : 1.5) )
```

- **×1.5** = weapons.js 原型相对校准量纲的实测比例(生产玩家战力/模型玩家战力 ≈ 1.5,多点位验证);
- **精英 ×1.3(而非 ×1.5)** = 引擎精英技能溢价补偿:实测引擎对精英波次(含 BOSS 技能)的胜率带比 §7 契约整体上移 ~15%(同比值下普通关 100% 胜、精英关 0–23% 胜,见 §9 数据),1.5/1.15 ≈ 1.3。**我表内 enemyPower 的精英 ×1.25 溢价保留在表值里,此处是引擎侧的额外补偿,不重复。**

逐关新锚点即 §3 总账最后一列(1:60 … 20:2163)。实现:`buildStages()` 里 `basePower` 改从上式取,`buildWaves` 入参不变(波次 atk/hp 与 power 线性,自动跟随);`balancePower` 字段可删(锚点已归一)。精英 `powerGate` 维持 R2 裁定 = 0。

**消融证据**:同策略同节奏下,不重锚 33/50 达标、p90 54;重锚(精英 1.3)**44/50、p50 34、p90 46**;精英若用 1.2 达 47/50 但 p50 34 偏快、墙感变弱;1.4 则 p90 66 超窗。若 gpt-sol 的 400 种子回归 p50 持续 < 38 分钟,**第一旋钮是精英系数 1.3 → 1.35**,不许动开局包与体力。

## 7. 配套裁定 B(阻塞达标):B1 强化曲线必须落地(opus-2)

R2 align §B1 原样重申:铜钱 `round(45 × 1.3^当前级)`、每级 +6%、上限 `{common:6, uncommon:9, rare:12, epic:15, legendary:18, mythic:21}`、碎片突破、验收锚点 +6→574 … +21→36,909。

**为什么阻塞**:旧曲线(60×L^1.35×品质系数、+12%/级、70 级上限)的铜钱→战力兑换率仅为校准值 ~40%,代理被迫无限银锻赌史诗,战力在 ~1800 平台期,20 关锚点(2163+)够不着——消融实验中换曲线前后是 16/50 → 29/50(其余变量不变)。stages.js 头注"原型高 1.5 倍所以不换强化曲线"不成立:量纲差已由 §6 的 ×1.5 吸收,强化曲线管的是铜钱水池的进出配速,与原型量纲无关。

**过渡等价式**(若 opus-2 本轮保留 `LEVEL_GROWTH 0.12` 面板不动,只换费用):生产 1 级 = 校准 2 级,第 p → p+1 级费用 = `round(103.5 × 1.69^(p−1))` 铜钱、无矿耗,上限 `{common:4, uncommon:5, rare:7, epic:8, legendary:10, mythic:11}`。首选仍是完整 B1。

## 8. 配套裁定 C:bench 策略与节奏修正(gpt-sol · economy-sim.mjs)

现策略五处偏离 R1 §8.1 代理规范,导致"经济健康但模拟不过"(R2 简报风险 5 的实锤):

1. **重试纪律**:首次挑战不设战力门槛(试一把 = 人类行为);失败后**战力 +3% 才许重试**,替换现在的 `lastBattleLost → 无限强化直到没钱才再战`(它在 0.83 比值连败 16 场烧掉 96 体力);
2. **白银炉从 `cleared ≥ 8` 进入候选**(现 `stage >= 10`;生产 `forgeWeapon` 本无门槛,策略自设的 10 与 balance `FORGE_UNLOCK_STAGE.silver = 8` 漂移);白银期停止给铁器喂强化,优先银锻→强化上阵银件;
3. **克制元素**:锻造时 `elementBias = 克制下一关元素者`(fire→ice→thunder→fire 反查),对应晶体 ≥ 2 才用;上阵按 `战力 × 元素系数` 排序而非裸战力。**这不是可选优化**:逆克制阵容对精英墙胜率恒 0%(§9),元素墙是设计内的解谜,晶体 faucet(首通 2–4 + 35% 掉率)就是为此供给的;
4. **批量分解**记一次操作(UI 本就是一键);
5. **节奏**:每分钟一操作 → §8.1 秒表预算:每分钟 60s,战斗 55s / 锻造 33s / 强化 9s / 批量分解 22s / 扫荡 13s(速通基准 × 2.2 休闲摩擦)。均匀 1 op/min 把校准配速人为拉长 ~2 倍(消融:同方案 p50 72 → 36 分钟)。

core `sweepStage` 落地后 bench 接入扫荡(卡关时体力→资源,见 §4)。回归护栏(替换 R2 align §H-7):**50 种子 90 分钟上限,达标 ≥ 42/50,p50 ∈ [30, 46],p90 ≤ 55,体力总消耗 p50 ≤ 110**。本文探针未建模碎片突破门槛与每日试炼分流,完整移植后 p50 预计 +2–5 分钟,窗口已预留。
