# 手工验收脚本（简体中文 · v1）

> Fable-4 维护。逐条对应 `docs/SOTA_CHECKLIST.md` 的编号（括号内标注）。
> 执行顺序建议：先跑 T12 自动化门，再按 T0 → T11 手测，最后 T13 红线核查。
> 全程保持 DevTools Console 打开：任何 error / 未捕获 rejection，当前用例判不通过并记 C4 失败。

## 0. 准备

```bash
cd games/xiangwang-shenghuo
npm install          # 首次
npm run dev          # 打开 http://localhost:4174
```

- 浏览器：Chrome 或 Edge 最新版；准备秒表（手机即可）。
- 常用控制台片段（下文以【清档】【读档】等指代）：

```js
// 【清档】纯净开局
localStorage.removeItem("xwsh.save.v1"); location.reload();

// 【读档】查看当前存档状态
JSON.parse(localStorage.getItem("xwsh.save.v1")).state

// 【坏档】写入非法存档（仅 T8 用）
localStorage.setItem("xwsh.save.v1", "{oops"); location.reload();
```

- 时间换算（默认 1 游戏时 = 6 秒）：1 游戏分 = 0.1 秒；1 日 = 144 秒；1 季 = 7 日 ≈ 16.8 分钟。
- 【夹具】与【快进】片段见附录 A / B，仅限标注了的用例使用。

1. 【清档】后等待页面加载。
2. 检查顶栏：`春 第1日 08:00`、`Lv.1`、`金币 80`、`幸福 40`、`温馨 20`、`人口 2/4`、按钮「声音：开」「记下这一天」。

5. 检查空状态文案：背包显示「口袋空空，去田里走走」；日志有开场白「蘑菇屋的门开了一条缝……」。

**过线**：以上全部符合；加载后 1 秒内可交互；控制台 0 error。

## T1 三分钟新手闭环（A1，P0）

前置：【清档】。从第一次点击起秒表计时。

1. 点「荒地」→ 变「空地」（开垦）。
2. 底部工具条点「种白菜」，点一块空地播种（−6 金币；春季错季，约 26 秒成熟）。
3. 点「种水稻」，点另一块空地播种（−8 金币；当季，约 18 秒成熟）。
4. 田块变金黄脉动后逐一点击收获（水稻 +2 稻谷 +6 经验；白菜 +2 白菜 +4 经验，有收获音效与日志）。
5. 心愿板「一棵白菜（白菜×1）」点「送去」，停表。

**预期**：
- 日志出现「心愿达成：一棵白菜，收入 16 金币」（14 金币 × 幸福 40 的 +16% 加成）；幸福 +1。
- 约 35% 概率日志追加「还捎来一把锹 / 斧子 / 锯子」（工具唯一来源，掉落由存档确定性决定）。
- 心愿补位节奏见 T2（GDD 目标：每 2 游戏时补 1 位；当前实现为交付后立即补满，如实记录）。

**过线**：≤180 秒完成第 5 步；0 报错。
**辅指标**：继续自然游玩，≤12 分钟内攒到 Lv2（40 经验）+ 80 金币 + 1 把斧子，点磨坊「建造」，再点「碾米」开工首单（连续实测 2 次取较好值）。
**已知风险**：若点开磨坊面板后内容瞬间被主界面刷掉、无法点「建造/开始」，记缺陷 UI-1，辅指标判不通过。

## T2 心愿屋节奏与掉落（A1 / A5 辅助）

前置：接 T1 存档继续。

1. 补位节奏（GDD 目标口径）：空位应在 2 游戏时（12±2 秒，灯哥在场约 10 秒）后补上，且一次只补 1 位。**当前已知偏差**：交付路径会立即补满 3 单（仅过期回收路径走 12 秒节奏），如实记录实测值。
2. 连续交付 3 单，记录工具掉落次数（期望约 1 次；权重 锹40% / 斧35% / 锯25%，珍珠 4%）。
3. 【快进】把 `day` +3 后刷新：挂满 3 日无人交付的心愿被撤下，日志出现「N 条心愿等太久，被从墙上取了下来」。

**过线**：补位有节奏（非每帧刷满）；掉落有日志；过期回收生效。

## T3 三条产业链（A2，P0）【夹具 A】

前置：注入附录 A 夹具（Lv6、全套建筑、原料齐备）后刷新。

链① 米→鸡蛋：
1. 点「磨坊」→「碾米」开始（稻谷×2 → 大米×1，10 秒）→「收取做好的」。
2. 点「饲料厂」→「粗糠鸡食」（大米×2 → 鸡饲料×2，8 秒）→ 收取。
3. 点「鸡舍」→「投喂」（−1 鸡饲料，20 秒）→ 收取，背包 +1 鸡蛋，经验 +5。

链② 豆→豆腐：
4. 点「磨坊」→「磨豆腐」（大豆×2 → 豆腐×1，12 秒）→ 收取，背包 +1 豆腐。

链③ 麦→面包：
5. 点「磨坊」→「磨面」（小麦×2 → 面粉×1，10 秒）→ 收取。
6. 点「厨房」→「烤面包」（面粉×1 + 鸡蛋×1，11 秒）→ 收取，背包 +1 面包。

**过线**：三条链终产物均入包；每次收取有音效与背包变化；0 报错。
**已知风险**：同 T1 的 UI-1（面板被逐帧重绘清空）。若复现，本用例判不通过，改以 `node scripts/chain-smoke.mjs` 退出码 0 作为状态层旁证记录。

## T6 嘉宾与烹饪（A4，P0）

1. 【清档】，右侧点「请灯哥」：温馨 20→24，日志「灯哥推门进来……说是住到第X日」。

## 附录 A 夹具存档（Lv6 演示状态，仅限【夹具】用例）

先【清档】进入新局，再在控制台执行：

```js
const raw = JSON.parse(localStorage.getItem("xwsh.save.v1"));
const s = raw.state;
s.meta.xp = 420;                                    // 等级由 xp 推导 → Lv6
s.resources = { ...s.resources, coin: 2000, shovel: 8, axe: 3, saw: 3 };
s.inv = { ...s.inv, paddy: 12, soybean: 12, wheat: 12, rice: 6, corn: 6,
          egg: 4, milk: 2, chicken_feed: 4, flour: 4 };
s.buildings = { ...s.buildings,
  mill:     { built: true, slots: [], slotCount: 2 },
  feedmill: { built: true, slots: [], slotCount: 3 },
  coop:     { built: true, slots: [], slotCount: 3 },
  kitchen:  { built: true, slots: [], slotCount: 2 },
};
localStorage.setItem("xwsh.save.v1", JSON.stringify(raw));
location.reload();
```

## 附录 B 快进（改游戏时间后刷新）

```js
const raw = JSON.parse(localStorage.getItem("xwsh.save.v1"));
raw.state.meta.day = 7;                  // 目标日
raw.state.meta.gameMinutes = 23 * 60;    // 23:00，约 6 秒后跨日（第 7→8 日即换季）
localStorage.setItem("xwsh.save.v1", JSON.stringify(raw));
location.reload();
```

> 提醒：夹具与快进都会改变确定性 RNG 的输入（掉落、黑暗料理由存档内容推导），
> 同一夹具 + 同一操作序列的结果可复现，跨夹具比较概率类数值时需多次采样。
