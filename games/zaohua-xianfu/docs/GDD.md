# 造化仙府 · 游戏设计文档

## 一句话

洞府经营 × 弟子养成 × 阵营回合自动战：从一座荒废仙府起步，聚灵、开田、招徒、炼丹锻器，率人/神/魔仙友登天塔、御兽潮，证道飞升。

## 参考原作

《造化仙府》（沛炫网络 / 微信小游戏 + 手游）核心卖点：仙府经营（洞府仙居决定建筑上限、灵脉邻接）、弟子专业养成、三阵营克制、事件触发式法器、登天塔与兽潮防御、离线放置产出。

本复刻为**公平网页单机**：无付费档、无抽卡氪金，强度只来自经营、阵容克制与节奏把握。

## 核心循环

1. 选阵营开府 → 2. 建/升建筑、派弟子生产 → 3. 吐纳修炼、破境提升三维 → 4. 组 6 人阵容打登天塔 / 兽潮 → 5. 首通掉法器、资源反哺经营 → 6. 更高洞府等级解锁新建筑 → 7. 更深塔层与兽潮波次。

### 产量公式

```
实际产量/秒 = 裸产量(Lv.1)
            × 等级系数 (0.85 + 0.15×Lv，Lv.12 = 2.65)
            × 弟子系数 (采集类 1 + 勤勉×0.018 + 专业×0.06；丹器阵 1 + 武力×0.01 + 专业×0.05)
            × 邻接系数 (见邻接规则，下限 0.5)
            × 府邸光环 (1 + 0.03×(洞府等级-1))
```

离线结算效率 = 50% + 6%×聚灵阵总等级，封顶 90%，离线上限 8 小时。

### 升级成本

```
wood = ⌈8 × 类型系数 × Lv^1.45⌉    ore = ⌈6 × 类型系数 × Lv^1.4⌉    stone = ⌈12 × 类型系数 × Lv^1.35⌉
```

系数 1.0 建筑的单级成本参考：Lv.2 = 木22/矿16/石31，Lv.5 = 木83/矿58/石106，Lv.8 = 木164/矿111/石199，Lv.12 = 木294/矿195/石344。战力类建筑更贵（丹房 ×1.25、锻造房 ×1.3、演武场 ×1.65），采集类便宜（灵田/木坊 ×1.0）。

### 邻接规则（mansion/layout 实现）

灵脉滋田 +15%/条（灵脉每高 1 级再 +2%）、灵脉润坊 +10%、脉阵相引 +12%、聚灵阵灌注丹房/锻造/藏经 +8%、府邸荫庇全体 +5%；**负邻接**：炉火燎田 -8%（锻造房邻灵田）、药烟熏苗 -5%（丹房邻灵田）。布局最优解：灵脉十字围田、丹锻远离田区。

## 阵营与克制

### 三角克制

**神克魔、魔克人、人克神**。占优方伤害 ×1.18，被克方 ×0.92（`factionAdvantage`）。差值约 28%，足以决定五五开的战斗，但可被一个境界差碾回来。

### 阵营风格

| 阵营 | 风格 | 强势期 | 终盘评价 |
| --- | --- | --- | --- |
| 人族 | 慈航群奶 + 姜子牙破甲的消耗流 | 全程稳，越拖越强 | 40+ 层首选：治疗随攻击成长 |
| 神族 | 光环 + 玄天盾 + 杨戬追击的中军流 | 中盘成型即碾 | 终盘第二：护盾在高攻敌前渐薄 |
| 魔族 | 悟空开场爆发 + 八戒嘲讽的速攻流 | 前中盘速通最快 | 终盘约慢半个境界：缺可持续回复，30+ 层需要多存一层修为再推；40+ 层靠防槽法器补续航（见「魔族续航与掉落节点」） |

前 16 人带专属战斗机制（战斗层 KITS 一一对应），新增 9 人为「通用技」仙友：秘技单体 155% 攻击；输出位攻速 1.05 秒/击（他位 1.25 秒）、辅助位秘技 4 秒一转（他位 6 秒），以更高裸三维立足。

### 克制的实战应用

- 塔的每章有主题阵营（见登天塔一节）：普通小队三系俱全（克制收益均摊），**章主固定为主题阵营**——克它的存档打章主省半个境界，被克的存档反之。
- 兽潮敌人三系轮转，无长期克制红利，比拼纯粹的阵容成型度。

## 法器（四槽）

### 槽型口径（AD-8 / G5.4，已实装）

四槽固定为 **攻 ×1、防 ×1、通用 ×2**（core/state.js 的 `ARTIFACT_SLOT_CAPS`，`ARTIFACT_SLOTS = 4` 由其求和导出），与 G5.4 验收一致：

- **佩戴（EQUIP_ARTIFACT）**：再点已佩戴的法器即卸下；佩戴新法器只在**本槽内 FIFO**——本槽满员时挤掉本槽最早的一件，绝不挤占其他槽（`equipArtifact`）。未知或缺失槽型的法器归入通用槽，保证装得上也卸得掉。
- **读档收敛（normalizeEquipped）**：只留拥有的法器，每槽超容量的按出现顺序丢弃。
- **数据侧配套（本轮拍板）**：**万魂灯归通用槽**。复活是「命数」类容错，不减伤不回血，不该占防位；若留在防槽，基准四件套（七星灯 + 万魂灯双防）在 1/1/2 制下非法，Round 1 进度墙全表作废。移槽后 七星灯（防）+ 万魂灯（通）+ 论道图（通）+ 朱雀弓（攻）恰好占满四槽合法——`simulate` 不读 slot，墙表数值不受影响，锚点保住；槽池分布亦更均衡（防 6 件争 1 席、通 8 件争 2 席、攻 6 件争 1 席）。
- **测试**：regressions 已锁「同槽淘汰、跨槽不挤占、1/1/2 容量」，Round 1 的四槽 FIFO 断言已随之改写（简报第 10 条闭环）。

### 机制类别与叠加规则

战斗层按 effect 形状数据驱动解析（combat/artifacts.js）：

| 类别 | 规则 | 叠加 |
| --- | --- | --- |
| 被动（passive） | 暴击率/秘技冷却相加，普攻/秘技增伤相乘 | 可叠 |
| 护佑（lowhpNN + 减伤） | 生命低于阈值时减伤 | 不叠加，取减伤更深者 |
| 自救（lowhpNN + 回血） | 全队合计一场一次 | 不叠加，取阈值更高者 |
| 复活 / 搏击 / 灼烧 / 斩杀 / 晕眩 | 各自唯一 | 不叠加，取后装 |
| 开场护盾（start） | 全队护盾 | **相加**（瑶光 18% + 定海 14% = 32%） |

**万魂灯口径拍板（P1-4 / G5.6，已闭环）**：以「每人每场一次」为准——**我方每名上阵者阵亡时各可复活一次**，战斗层按 data 的 `effect.reviveHp` 每单位挂复活次数（`effect.reviveCharges` 可覆写，缺省 1），data 文案与战报已同步。不取「全队一场一次」：进度墙 30 seed × 3 阵营仿真以每人一次校准，改机制须整表重标；红品占一席通用槽（挤掉一件被动）的机会成本已计入定价。注意与自救（阴阳镜/三光）区分：自救是全队合计一场一次。combat-artifacts 测试已锁「多名队员各复活一次、复活者互不重复」。

## 登天塔

### 结构

每章 10 层，章节主题循环：青丘妖狐林 → 黑风山寨 → 幽冥血泽 → 雷音废刹 → 九幽魔渊 → 域外天魔界（之后循环，压力继续按层数复利）。

- 第 3 / 8 层：**精英层**（×1.16 三维）。
- 第 5 层：**护法首领**（守关 BOSS，×1.85 血 ×1.24 攻）。
- 第 10 层：**章主**（×2.15 血 ×1.32 攻，主题阵营，掉落节点）。
- 敌人数量：普通层 3→4（18 层起）→5（36 层起）；首领层 4→5（26 层起）。
- 战斗限时 60 秒，超时按存活人数判定——拖不死人也要拖得过人数。

### 数值曲线

```
攻 = (16 + 6.4×层) × P    血 = (240 + 102×层) × P    防 = (5 + 2×层) × P
P(层) = 1.045^max(0, 层-20) × 1.07^max(0, 层-30)
```

三段设计：**1–20 层线性**（跟着境界走就能推）；**21–30 层温和复利**（要求六人满阵 + 塔掉法器 + 丹房锻造房到位）；**31 层起双段复利**（每个境界只再放行 3–4 层，章主全是硬墙）。

## 兽潮

- 波次敌人：`攻 = (14+6×波)×P，血 = (210+85×波)×P，P = 1.06^max(0,波-10) × 1.08^max(0,波-20)`；数量 2+⌊波/3⌋（上限 6）。
- 每 5 波潮元首领（×2.0 血 ×1.25 攻）；兽群每 8 波换代：妖狼 → 铁背妖猿 → 岩甲地龙 → 罡风妖禽 → 上古凶兽（循环）。
- 敌方阵营三系轮转，无克制红利，是阵容成型度的试金石。
- 胜：灵石 14+3×波、灵气 20+2×波、灵草 6+波，每 5 波仙玉 3。**败：未收取的产出尽数散失，已入库资源分毫不动**——兽潮是「以挂机匣为赌注」的模式，推潮前先开匣收产。
- 进度墙实测：练气 8 → 7 波；金丹 3 → 12 波；元婴 8 → 18 波；合体 9 → 28 波。

### 败仗税口径（AD-12，已实装）

- 税基 = **未收取的产出**（core/store.js 的 `waveLossTax`）：挂机匣里未领的一笔全数散失；上次入账到此刻之间尚未进库的一小段府产（≤ 一个 TICK，2 秒）一并作废（`lastTick` 推到当下）。已入库的七资源分毫不动，波次不回退，败仗日志逐项列清散失明细；regressions 已锁「只折未收取产出」。
- Round 1 的「库存灵草/灵木/灵矿各扣 30%」**废弃**：抄家式惩罚迫使玩家每次推潮前把库存花空，把挑战前置成仪式性搬家。改为「以挂机匣为赌注」后，决策点变成**先收匣再推潮**——败仗代价与离线积累挂钩，玩家可用一次点击把风险归零，激进连推（匣里越攒越多）才承担真实赌注。
- 文档同步：ACCEPTANCE G5.2「失败散失三成灵草/灵木/灵矿」为旧口径残文，须随本口径改写；combat/wave.js 中 `waveReward` 的败仗 `loseTax` 分支（库存 30%）已无调用方，属死代码，待机制所有者删除（简报第 8 条同类收口）。

## 数值验证

平衡由仿真驱动：用真实 `simulate` 以 30 seed × 3 阵营在 9 个进度检查点扫层（检查点 = 境界层数 + 上阵人数 + 建筑战力 + 法器四件套），墙位见上表。回归基线：`npm test`（24 用例）、`npm run bench`（200 场 <800ms）、`npm run probe`（契约完整性）。

## 公平性

无内购、无抽卡概率付费。仙友以仙玉礼聘（仙玉全部产自经营与挑战），法器全部来自首通掉落，强度只来自经营决策、境界积累与阵容克制。
