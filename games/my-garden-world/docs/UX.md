# UX 说明 · 我的花园世界

本文档归 fable-ux 维护，描述新手教程、核心交互流程、空/错误状态与移动端手势。涉及文件：`src/data/story.ts`（剧情与门槛数据）、`src/ui/tutorial.ts`（教程渲染与门槛判定）。

其中一至五节描述**已实现**行为；六、七两节是 Round 2 的**设计稿**（邻家花园互访、装扮摆放模式），交由对应系统槽位实现；八节的可选剧情折（番外）**已实现**数据与渲染 API，等待玩法系统接线触发。

## 一、新手教程（六折，行为门控式）

教程共六折，采用「折」作章回单位。第一折与最后一折是纯剧情；中间四折各带一个**行为目标（goal）**：先弹出开场折子交代剧情与目标，收起后化为**底部引导横幅（coach）**，由真实的玩法事件推进，玩家不完成操作无法进入下一折。

| # | id | 标题 | goal | 推进事件 | 新解锁 dock |
|---|----|------|------|----------|--------------|
| 一 | `wake` | 荒园来信 | 无 | 点按即过 | — |
| 二 | `sow` | 下一粒种 | `plant` | `planted` | 花种 |
| 三 | `water` | 引一瓢水 | `water` | `watered` | 洒水 |
| 四 | `harvest` | 剪一枝花 | `harvest` | `harvest` | 收获、施肥 |
| 五 | `order` | 接头一单 | `order` | `orderDone` | 订单、库存 |
| 六 | `open` | 自此看花 | 无 | 点按或 Esc 收起 | 花艺、装扮、花灵、扩建、访邻¹ |

¹ `visit`（访邻）已写入尾折 `allow` 作预留门控位：dock 按钮落地后无需改教程数据即随开园解锁；按钮存在前该 id 不产生任何可见影响。

设计要点：

- **剧情折**（一、六）居中大幅模态呈现，营造章回感；**goal 折**先弹折子（含「第X折 · 共六折」进度与「◌ 目标 · ……」行），点按 cta 后收起为不遮挡的 coach 横幅，让出整座花园。
- **dock 渐进解锁**：教程期间 dock 按钮按当前折的 `allow` 列表累积点亮（音效/重整常开），当前目标按钮带金圈呼吸高亮（`coach-target`），玩家一眼可见下一步在哪。
- 推进是**事件驱动**的（planted/watered/harvest/orderDone），不轮询、不锁存也不会回退——完成动作瞬间进入下一折。
- **保底订单**：第五折若列表中没有雏菊订单，`ensureTutorialOrder` 会补一张长时限的「邻家阿姊」单，防止随机订单让新手卡关。
- **键盘 Esc**：仅最后一折生效，按下即收起教程开园（折子上有「按 Esc 键亦可收起」提示）；前五折按 Esc 无效，goal 门槛不可跳过。

### 与 app.ts 的接口契约

- `renderTutorial(host, state, onNext)`：只在 `tutorialStep/tutorialDone` 变化时由外层调用；goal 折的折子→横幅切换由模块内部处理。
- `tutorialEventAdvances(state, event)`：事件总线上判断当前折是否应被该事件推进。
- `advanceTutorial(state)`：步进 `tutorialStep`，走完置 `tutorialDone`。
- `tutorialAllows(step, done, buttonId)`（`data/story.ts`）：dock 门控；`coachTargetId(state)` 给出高亮目标。

## 二、核心交互流程

主循环：**播种 → 浇水（→施肥）→ 收获 → 插花/交付订单 → 装扮庭院、请花灵**。

1. **选圃与工具**：底部工具栏切换洒水/施肥/收获工具后点按花圃生效；点圃同时会选中它（金框高亮）。无工具时点按盛放/枯萎的花直接收获（smart-tap）。
2. **播种**：开「花种」面板 → 点花卡选中花种（卡片按下态 + 空圃泛绿邀请光）→ 点任意空圃连续播种；再点卡片取消选择，切换工具亦会清除。
3. **浇水**：切「洒水」后点按花圃，或**按住拖过多块花圃连续浇灌**（见移动端手势）。花圃上的水滴点（pips）显示 已浇/需水；水缸每 8 秒回 1 滴，订单奖励也回水。
4. **收获**：花开（「可收」标签）后用「收获」剪下入库；拖过花期会凋残（「凋残 · 速收」），只回两成残值、不入库。
5. **订单**：「订单」面板列出客人需求与倒计时；花材/作品齐备时「交付」可点，缺什么会在按钮提示里写明。「婉拒」换新客但损 4 点口碑；订单超时同样损口碑。
6. **花艺作坊**：选 2–4 枝库存花材、择一花器成作评分；高分作品用于交付定制订单。
7. **装扮与花灵**：金币/碎片购置装饰、套主题；升阶解锁花灵，驻园给增益。

## 三、空状态与错误状态

### 面板空状态（占位文案，非弹窗）

| 场景 | 文案 |
|------|------|
| 订单面板无单 | 客人正在路上…… |
| 作坊无库存花材 | 库存空空，先去花圃收获。 |
| 作坊无陈列作品 | 陈列：空，成作后可交付定制订单。 |
| 库存面板为空 | 匣中空空，去花圃收获几枝吧。 |
| 花种卡不可种 | 还差 N 金 / 暂无空圃（卡片置灰并注明原因） |
| 空花圃 | 圃面显示「空圃／待播种」水印 |

### 错误与受阻状态（warn 色 toast，自动消散、可点按关闭）

| 操作 | 文案 |
|------|------|
| 播种钱不够 | 金币不足，买不起这袋种子 |
| 浇水没水 | 水缸空了，等一等或去做订单 |
| 交付缺指定花 | 花材尚未备齐 · 还缺某花 |
| 交付缺任意花 | 库存花材不足 · 还差 N 枝 |
| 定制单无作品 | 定制单要凭作品交付，先去作坊插一瓶 |
| 定制单分不够 | 这件作品还配不上定制 · 需 N 分 |
| 插花枝数不对 | 请放入 2 至 4 枝花材 |
| 未选花器 | 请先选一只花器 |
| 婉拒订单 | 客人离去，口碑微损 |
| 订单超时 | 客人久候不至，口碑微损 |
| 扩建钱不够 | 扩建需 N 金 |
| 收获凋残花 | 某花已凋残，只清出些许残料 |
| 花灵未解锁 | N 阶后方可请某花灵 |

原则：**受阻必有回声**——任何点了没生效的操作都给一条 warn toast 说明原因与出路（等水回、去做订单、先去作坊……），不做无声失败。相同文案短时间连发会合并成一条并计数。

## 四、移动端手势

- **点按（tap）**：按下与抬起落在同一块花圃视为点按，执行当前工具（种/浇/肥/收）。
- **拖拽浇水（drag）**：洒水工具下按住并扫过花圃，途经的每块按 220ms 节流各浇一次，指尖处溅起水花粒子并伴水声。用 `elementFromPoint` 命中，手指可连续拖过相邻花圃；舞台 `touch-action: none`，拖拽不会触发页面滚动。
- **coach 引导横幅**悬浮于 dock 上方且限宽，不遮花圃与工具栏；剧情折全屏模态在小屏（≤640px）收紧内边距。
- toast 与教程横幅均计入 `safe-area-inset-top`，避开刘海。
- 面板（sheet）从底部升起、内部可滚动，小屏最大高约 62vh，不盖住工具栏。

## 五、键盘与读屏

- `Esc`：分场景收起「当前最上层的临时物」——教程最后一折收起开园（前五折无效，goal 门槛不可跳过）；番外折随时可收起（见八）；摆放模式与邻家庭院中退出该模式（见六、七，设计稿）。同一时刻只有一层响应，不会一键连穿。
- 花圃是 `<button>`，天然可 Tab 聚焦、Enter/Space 触发当前工具；每块地的 `aria-label` 播报中文状态（「花圃3：碧桃，含苞，进度百分之60，缺水」）。
- 工具按钮带 `aria-pressed`，教程折子为 `role="dialog"` 且自动聚焦 cta，toast 区为 `aria-live="polite"`。
- `prefers-reduced-motion` 下粒子、摇曳与脉冲全部停用。

## 六、邻家花园互访（设计稿 · Round 2）

单机版「好友互访偷花」：邻居是本地 NPC，无网络、无真人。目标是给核心循环加一处**每日外出的理由**——帮邻居浇水攒友谊、借（偷）一枝自家还没有的花回来。

### 6.1 入口与解锁

- dock 面板组新增「访邻」按钮：`id: "visit"`、印章「邻」、`aria-label`「串门去邻家花园」。
- 门控已预留：`visit` 在教程尾折 `allow` 中，随「开园」解锁；教程期间同其他后期功能一样置灰。
- 邻居取自订单文案里已出场的人物，保持世界观连贯：**邻家阿姊**（1 阶即识）、**茶寮掌柜**（3 阶结识）、**东篱客**（5 阶结识）。未到阶的邻居在列表中以剪影卡呈现「N 阶后来往」。

### 6.2 邻家花园的生成

- 每位邻居的园子按 `邻居id + 游戏日` 作种子程序化生成：花圃 4–8 块、花种从该邻居的偏好池中取、生长阶段随机。
- **保底原则**（同教程保底订单思路）：生成器保证至少 2 块有花、至少 1 块缺水、至少 1 块盛放——串门必有事可做，不出「空手而归」的挫败。
- 园子是**只读快照**：邻家的花不生长、不凋残，互动结果记在自己的存档里，当日内重复进入呈现一致（含已浇/已摘痕迹）。

### 6.3 状态与数值（字段建议，最终数值以 GDD 为准）

```ts
// GameState 增量（由邻访系统实现方落地）
social: {
  day: number;                          // 游戏日戳，跨日重置余量
  waterLeft: number;                    // 今日剩余帮浇次数（每邻居上限 3）
  pickLeft: number;                     // 今日剩余摘花枝数（全局 2，每邻居 1）
  friendship: Record<string, number>;   // 邻居id → 友谊值，0–5 心档
  marks: { neighborId: string; plotIdx: number; kind: "water" | "pick" }[]; // 当日互动痕迹
}
```

- 帮浇水**不耗自家水缸**（邻家有自己的水缸），每次友谊 +1、经验 +2。
- 摘花仅限「盛放」花圃，摘得的花与自家收获同规格入库；被摘的圃当日显示「借花笺」纸条。
- 友谊满档奖励碎片并解锁该邻居的问候语变体；数值曲线归 GDD 管。

### 6.4 主流程

1. 点 dock「访邻」→ 底部 sheet 列出邻居卡：印章头像、名号、友谊心档（❤×N）、今日余量摘要（「可浇 3 · 可摘 1」）、「串门」按钮。
2. 点「串门」→ 宣纸横卷划场（约 300ms，`reduced-motion` 下直切）→ 进入邻家庭院。
3. 邻家庭院布局：顶部**访客横幅**（「阿姊家的园子」+ 问候语一句 + 「回自家园」按钮）；自家 dock 隐藏，底部换**访客动作条**：帮浇水 / 摘花 / 回家，样式同 dock 印章按钮。
4. **帮浇水**：选中动作后点/拖缺水花圃（复用 220ms 节流拖浇手势与水花粒子）；圃上水滴点补满，友谊飘字 +1。
5. **摘花**：盛放花圃泛金光可摘；点按剪下 → 花瓣爆开粒子 → 入自家库存，圃面换「借花笺」。
6. **回家**：动作条「回家」／横幅「回自家园」／`Esc` → 划场返回；返回时弹一条 ok toast 小结：「串门小记：浇了 3 瓢水，借得 1 枝碧桃，友谊 +3」。
7. 访问期间自家园子**时间照常流动**（不冻结 `now`）；进入访邻列表时若自家有 30 秒内到期的订单，横幅下加一行 warn 提示「家里有客急等交花」。

### 6.5 空状态

| 场景 | 表现与文案 |
|------|-----------|
| 邻居未到结识等级 | 剪影卡置灰：「三阶后来往」（不隐藏，留期待） |
| 今日互动余量用尽 | 邻居卡余量行显示「今日已叨扰，明日再来」；「串门」仍可点，进园只看不动 |
| 邻家无盛放花（保底外的极端） | 摘花动作置灰，按钮下注「花还没开，改日再摘」 |
| 邻家无缺水圃（都浇过了） | 帮浇水动作置灰，注「阿姊园里今日水足」 |
| 进园后无事可做 | 横幅问候语换为「坐坐就好，明日再来帮衬」——只看不动也成立 |

### 6.6 错误与受阻（warn toast，沿用「受阻必有回声」）

| 操作 | 文案 |
|------|------|
| 摘花超全局日限 | 今日已借两枝，再摘要伤和气 |
| 摘同一邻居第二枝 | 一家只借一枝，去别家看看 |
| 摘未盛放的花 | 花未开，摘不得 |
| 帮浇水超日限 | 今日帮浇的水够了，留点明日 |
| 给不缺水的圃浇水 | 这圃不缺水（同自家逻辑，轻提示不计次） |
| 教程期点访邻 | dock 门控置灰，不可点（无 toast，与其他锁定按钮一致） |

### 6.7 移动端与读屏

- 访客动作条固定于底部安全区上方；拖浇手势、`touch-action: none` 与自家一致。
- 邻家花圃仍是 `<button>`，`aria-label` 加前缀：「阿姊家花圃2：碧桃，盛放，可摘」。
- 进出邻家时以 `aria-live="polite"` 播报「进入阿姊家的园子」「回到自家园子」。
- `Esc` = 回家；划场动画在 `reduced-motion` 下省略。

## 七、装扮摆放模式（设计稿 · Round 2）

现状：`placeDecor` 只把 id 计入 `placedDecor` 数组，场景中**不可见**、无位置概念（Round 1 头号缺口）。本节设计**锚位制摆放模式**，配套装饰的庭院落位渲染。

### 7.1 锚位制

- 庭院四缘预设 **8 个锚位**：檐下、门前、径旁东、径旁西、池畔、墙角南、墙角北、园心。锚位绝对定位于舞台边缘装饰带，**不遮花圃、不随扩建移动**。
- 每个锚位至多一件装饰。DOM 实现即可（`<button class="anchor">`），无需自由拖放坐标系——与花圃网格同构，成本低且天然可及。
- 数据升级建议：`placedDecor: string[]` → `{ id: string; anchor: string }[]`；旧存档迁移：按数组顺序自动落到默认锚位序列（檐下→门前→…），一次性完成、无感知。

### 7.2 进入摆放模式

三个入口，殊途同归：

1. **购买即摆**：购置成功的 ok toast 附「去摆放」可点按钮（toast 已支持点按），点击手持新装饰进入摆放模式。
2. **布置栏**：装扮面板分「购置／布置」两栏；布置栏列出已购装饰（标注「已摆·檐下」或「在匣」），点「摆放／挪动」手持它进入。
3. **调整布局**：布置栏顶部「调整布局」按钮，空手进入，可自由拿起与挪动已摆装饰。

进入后：面板收起、`root.dataset.mode="place"`、8 个锚位标记浮现——**空位泛绿呼吸光**（复用播种邀请光语义：绿光=可放），**占位显示装饰印章缩样 + 琥珀描边**。右上角出现浮动「完成」按钮。

### 7.3 摆放交互（tap-tap 为主，与播种一致）

| 手势 | 行为 |
|------|------|
| 手持装饰 + 点空锚位 | 落座：印章落定动画 + 尘土小粒子 + ok toast「纱灯安在檐下」 |
| 手持装饰 + 点占位锚位 | 替换：原物回匣（不退款，仍归你所有），toast「换下风铃，收回匣中」 |
| 空手点已摆装饰 | 拿起变半透明幽灵章跟随指针，原锚位转空 |
| 手持中点「回匣」浮钮 | 收回不摆，装饰回布置栏「在匣」 |
| 点「完成」／`Esc`／再点 dock「装扮」 | 退出摆放模式，立即入存档 |

- 所有操作**可逆、不弹确认框**——挪动零成本，试错即玩法。
- 一键主题（`applyTheme`）自动按主题偏好锚位落座；锚位不足时换下 mood 最低的非主题装饰，退出时一条 toast 汇总「秋宴入园：屏风·池畔，稻草翁·园心；风铃回匣」。

### 7.4 空状态

| 场景 | 表现与文案 |
|------|-----------|
| 布置栏无已购装饰 | 「匣中无一物，先去购置栏看看。」+「去购置」跳栏按钮 |
| 全部锚位已满且手持新装饰 | 锚位全部琥珀色，舞台顶提示条「园中已满，点一处换下旧物」 |
| 购置栏全部未达阶 | 卡片置灰注「N 阶解锁」（现状已有，保持） |
| 摆放模式中无手持、无已摆 | 不可能态（布置栏空时「调整布局」不可点）；保底：任何时刻 `Esc` 都能退出 |

### 7.5 错误与受阻

| 操作 | 文案 |
|------|------|
| 手持时点非锚位区域 | 最近的空锚位轻晃 + 提示「点亮处才可安置」（同文案 3 秒内不重复） |
| 教程期开装扮 | dock 门控置灰（第六折才解锁，现状已有） |
| 购买时金币碎片都不够 | 「金币或碎片不足」（现状已有，保持） |
| 重复购买同款 | 「庭中已有此物」改为「匣中已有此物」——落位制下同款只购一次的规则不变 |

### 7.6 移动端与读屏

- tap-tap 选中→落座为主手势；长按已摆装饰 350ms 直接拿起为增强手势（可选）。
- 幽灵章在触屏上悬于指尖上方 24px，避免被手指遮住。
- 锚位是 `<button>`：`aria-label`「檐下：空位，点按安置」／「檐下：纱灯，点按替换」；进出模式经 `aria-live` 播报「进入摆放模式」「布置已保存」。
- `reduced-motion` 下呼吸光改为静态绿描边，落定动画省略。

## 八、可选剧情折（番外）· 已实现 API

为六、七两个新玩法配的**一次性剧情弹窗**，营造「章回外的闲话」。与主教程完全解耦，不改变任何既有教程 API 的签名与行为。

### 8.1 数据（`src/data/story.ts`）

`SIDE_STORIES: SideStory[]`，三折，字段 `id / trigger / title / body / cta`；`sideStory(id)` 查询：

| id | 触发时机（trigger） | 标题 | 内容一句话 |
|----|--------------------|------|-----------|
| `fence` | `visit-first`·首次进入邻家庭院 | 篱外人家 | 阿姊隔篱相邀，交代串门礼数（浇缺处、摘盛开、莫贪多） |
| `borrow` | `visit-pick-first`·首次摘邻家花成功 | 借花一枝 | 「花开堪折直须折」，点出借花记情的往来循环 |
| `settle` | `place-first`·首次进入摆放模式 | 一物得其所 | 货郎送货上门，交代锚位规则（微光=空位，可随时挪） |

### 8.2 渲染（`src/ui/tutorial.ts`）

`renderSideStory(host, state, id, onClose?) => boolean`：

- 复用 `.modal / .modal-card` 现有样式（零 CSS 改动），类名 `modal side-story`（**不带** `tutorial`，避免被 `renderTutorial` 的清场逻辑误删）；眉标「番外 · 闲话一折」。
- **守卫**：`tutorialDone` 为假不弹（主教程优先）；同一 id 每会话只弹一次（内存态，同 goal 折的 `introSeen`）；屏上已有一折番外时不叠弹。被守卫拦下时安静返回 `false`，弹出返回 `true`——调用方无需自己记状态。
- 收起：点 cta 或按 `Esc`（自带独立 keydown 监听，关闭即移除，不与主教程的尾折 Esc 绑定共享状态）；收起后回调 `onClose`。
- `role="dialog"` + `aria-modal` + 自动聚焦 cta，与教程折子同规格。

### 8.3 兼容性不变式

- `renderTutorial / advanceTutorial / currentBeat / tutorialEventAdvances / coachTargetId / tutorialAllows` 签名与行为**一字未动**；`TUTORIAL` 仍是六折，番外不占 `tutorialStep`、不推进 `tutorialDone`、不参与 dock 门控。
- 唯一的教程数据变更：尾折 `allow` 追加 `"visit"` 预留位（见一节脚注），在 `visit` 按钮落地前无任何可见影响。
- 接线指引（给六、七的实现方）：对应时机直接调 `renderSideStory(root, state, "fence" | "borrow" | "settle")` 即可，无需判重。
