# 游戏设计文档 · 我的花园世界（致敬仿写）

## 一句话

扮演穿越花艺师，把荒废宅第花园经营成四季繁花的国风花坊。

## 玩家幻想

在墨色亭台与锦鲤池边，亲手育花、配器插花、接待来客，让一座废园重新开花。

## 核心循环（30 秒）

选种播种 → 浇水/施肥催熟 → 收获花材 → 花艺作坊配器成束 → 交付订单得金币/经验 → 扩建花圃与装扮庭院 → 解锁花灵与更高阶花种。

## 生长阶段

`empty → seeded → sprout → bud → bloom → wilt(超时未收)`

每阶段需水分；缺水停滞。施肥缩短剩余时间。季节匹配时生长倍率 1.35，错季 0.75。花灵可再乘加速。季节每 4 个游戏日（约 6 分钟真实时间）轮转一圈，单季约 90 秒。

## 花种图鉴（24 种 · 四季各六）

每季配置：1 种廉价快花（★，任何季节开局都有活钱）、若干中坚（★★~★★★）、1 种高阶（★★★★）、季末稀有（★★★★★）。

Round 2 起每种花带两个品质标签（`src/data/flowers.ts`）：

- **色系 `hue`**：赤/粉/金/素/紫/青/翠 七系（中文名见 `HUE_NAMES`）。配色评分与器花相契一律以色系为准，不再用 `color` 十六进制（24 种花的十六进制互不相同，按它算配色永远满分、毫无决策）。
- **章法 `role`**：主花 focal / 配花 filler / 衬花 accent（中文名见 `ROLE_NAMES`）。一瓶恰一枝主花为正；配花可多枝；衬花是各季的 ★1 小花。

## 花艺作坊

选择花器（陶瓶/青瓷/竹筒/青铜，加成 4/8/6/10）+ 2~4 枝花材。

**现行评分公式**（Round 2 已上线，`src/systems/workshop.ts scoreBreakdown`）：

```
总分 = clamp(round(底分4 + 稀有 + 配色 + 时令 + 和鸣 + 满瓶 + 花器), 0, 100)
稀有 = min(34, Σ稀有度 × 2.6)
配色 = min(24, 不同花色数 × 3.5)      ← 现按 color 十六进制，Round 3 改按色系
时令 = min(28, 当季枝数 × 5)
和鸣 = 枝数≥3 时按花材横跨季数：一季 10 / 两季 7 / 更多 0
满瓶 = min(6, (枝数−2) × 3)           ← Round 3 改为章法分
```

**品第**（`ARRANGEMENT_TIERS`，阈值对齐定制订单）：凡品 0 / 雅品 60 / 精品 75 / 神品 92。作品名自动缀品第，toast 分色。

现行公式对全部 2~4 枝不重复组合 × 四季（青铜为最坏情况）的分布：上限 98、神品占比 0.09%、凡品 14.3%——「评分易满 100」已修复；遗留问题与 Round 3 深化见「接线清单」。

## 订单（29 张模板）

- 居民订单：点名 1~2 枝具体花材，经验与水滴偏多、金币偏少（13 张，覆盖 1~10 阶）
- 花艺定制：指定作品评分档，60 / 70 / 75 / 85 / 92 五档（5 张：1/2/6/5/9 阶）
- 绸缎/建材：交任意或点名花材，换大量水滴（5 张，3~13 阶）
- 组团订单：点名主花 + 任意配花凑数，量大限紧、赏金最高（6 张，6~12 阶）

模板语义：`flowerIds` 为点名花材（重复点名即多枝）；`flowerCount` 超出点名部分按「任意花材」结算，系统自动取库存中最廉价的几枝补足。纯「任意花材」的订单赏金按廉价花估值，防止白送高价单。

**同款去重**（Round 2 已上线）：`spawnOrders` 保证列表内不出现两张同模板订单，且刚交付/超时的模板不会立刻原样贴回；模板不够铺满栏位时才退让。教程保底雏菊单不受此限。

**抽取权重 `weight`**（数据已就位，接线见清单）：居民 3~4 / 定制·绸缎 2 / 组团与顶级单 1。各阶候选池权重占比（仿真）：1 阶居民 86%，10 阶居民 62% · 定制 17% · 绸缎 15% · 组团 7%——大单稀客的体感靠权重而非硬门槛。

定价基准：居民单 coin ≈ 0.70~0.75 × 点名收成；绸缎单 ≈ 0.75~0.9 × 收成但水滴丰厚；组团单 = 0.7 × 点名收成 + 任意补枝估值(≈15/枝) + 三成上下组团溢价。榜首为 12 阶「梦幻婚典百花轿」430 金。

退单降低「口碑」（−4，下限 30），口碑影响客单价（见花灵）。

## 花灵

解锁后驻园，同时仅一名出战。定位互斥：后位花灵不在加速上反超菊月，改以功能与口碑取胜。

| 花灵 | 解锁阶 | 加速 | 特长 |
|------|--------|------|------|
| 菊月 | 4 | ×1.6 | 纯加速 |
| 池光 | 7 | ×1.25 | 自动浇灌 · 口碑 +2 |
| 虹蝶 | 10 | ×1.15 | 护花不凋 · 口碑 +4 |
| 雪衣 | 13 | ×1.2 | 护花不凋 · 口碑 +6 |
| 岁灯 | 15 | ×1.45 | 自动浇灌 + 护花不凋 · 口碑 +8（毕业灵） |

**口碑接线**（Round 2 已上线，`src/systems/economy.ts`）：`有效口碑 = min(100, 口碑 + 出战花灵 reputationBonus)`，未苏醒的花灵不作数；客单价 `moodBonus = 1 + min(0.35, 摆件数×0.04) + (有效口碑−70)/400`。岁灯满级相当于永久 +2% 客单价，与装扮心境加成叠加。

## 装扮

地块外的庭院层，共 12 件：纱灯、檐下风铃、青石径、花架秋千、花鸟屏风、稻草翁、锦鲤池、雪狮、暖手铜炉、半亭、九曲小桥、月洞门。

主题套装：春晓 / 盛夏 / 秋宴 / 冬雪 / 墨雅，可一键套用再微调。每件摆件为订单赏金提供 +4% 心境加成，上限 +35%（约 9 件到顶）。

## 数值守则

- 种价必须低于收成：`seedCost < harvestCoin × 1.15`（probe 抽查按 1.2 上限兜底）
- 生长时长 `growMs > 5000`，最快的花也留出可感知的养成节奏
- 订单 `coin > 0`、`timeMs > 10_000`、`weight ≥ 1`；运行时寿命夹在 15 秒 ~ 10 分钟
- 点名花材的解锁阶 ≤ 订单 `minLevel`，玩家等级够接单就一定种得出
- 任一等级的候选模板数 ≥ 订单栏位数 `3 + min(2, level/4)`，同款去重永不因池小而卡死
- 定制订单的评分档在 `minLevel + 1` 阶内可达（不重复花材、青铜瓶、任选季节口径，与 round2-economy 测试一致）
- 章法覆盖：每季恰 1 衬花、≥2 配花、≥1 主花；色系每季 ≥ 3 系
- 每分钟净收益随稀有度/解锁阶单调上升：★ 约 20~25 金/分 → ★★★★★ 约 137~146 金/分

## Round 3 接线清单（系统代理必读）

数据层（`src/data/**`）已就位、单测全绿；以下改动属系统层，按清单接线即可，所有数值结论都经 2~4 枝全组合 × 四季 × 四器仿真验证。

### A. 订单权重抽取（1 行）

`src/systems/orders.ts` 的 `spawnOrders` 内，把

```ts
const t = pool[Math.floor(Math.random() * pool.length)];
```

换成

```ts
const t = pickWeighted(pool, Math.random());   // 从 ../data/orders 导入
```

去重、兜底、教程保底逻辑一概不动。`pickWeighted` 是纯函数（roll 注入），空池返回 `undefined`，边界 roll=0/1 已验证，命中率与权重占比偏差 < 0.001%。现有 round2-economy 的订单测试全部兼容（它们只断言去重与数量，不断言均匀分布）。

### B. 评分深化：色系配色 + 章法 + 重样折价

目标：把配色从「十六进制必然满分」变成真决策，把满瓶分从「凑够四枝白送」变成章法决策，并堵住「同种花材堆叠」把曲线压扁的漏洞。只动 `src/systems/workshop.ts scoreBreakdown` 的两个分项、再加一条折价，其余常数（底分 4、稀有 ×2.6 封 34、时令 ×5 封 28、和鸣 10/7、花器 4/8/6/10、clamp 0..100）不变：

1. **配色改按色系**（替换 `PALETTE_PER_COLOR`/`PALETTE_CAP`）：

```ts
const PALETTE_BY_HUE_COUNT: Record<number, number> = { 1: 8, 2: 12, 3: 6, 4: 2 };
const palette = PALETTE_BY_HUE_COUNT[Math.min(4, new Set(defs.map((d) => d.hue)).size)] ?? 2;
```

双色相映 12 > 一色素雅 8 > 三色 6 > 四色斑杂 2。

2. **满瓶改为章法**（替换 `FULLNESS_PER_STEM`/`FULLNESS_CAP`，上限仍 6）：

```ts
const focal = defs.filter((d) => d.role === "focal").length;
const composition = (focal === 1 ? 4 : 0)
  + (defs.some((d) => d.role === "filler") ? 1 : 0)
  + (defs.some((d) => d.role === "accent") ? 1 : 0);
```

恰一枝主花 +4（双主花喧宾夺主记 0），有配花 +1，有衬花 +1。

3. **重样折价**：同种花材第 2 枝起每枝 −4，folded 进 composition 一起入总分：

```ts
const dupPenalty = (defs.length - new Set(flowerIds).size) * 4;
```

`ScoreBreakdown` 接口建议把 `fullness` 重命名为 `composition`（值 = 章法 − 重样，可为负）；重命名只牵动 round2-economy「breakdown 一致性」测试里求和的那一行。

**接线后的验证基准**（接线完成后建议直接抄进 probe）：

- 全组合（含同种多枝、任选花器）上限 **92**，恰好 3 个满分组合，全在秋季青铜瓶：星辰郁金香+彼岸花+枫叶兰+雁来红 / 星辰郁金香+双彼岸花+雁来红 / 秋菊+金桂+枫叶兰+彼岸花
- 不重复组合 × 四季 × 青铜的品第分布：凡品 53% / 雅品 46% / 精品 2.7% / 神品 0.004%（2 例）
- 各评分档首达等级（允许同种多枝、任选季节与花器）：**60→1 阶、70→2 阶、85→4 阶、92→8 阶**；等级×季节最佳分平原在 87~92，四季各有专属大建
- 五张定制单在 `minLevel+1` 口径全部可达：60/70/75/85/92 → best 73/75/86/86/92（后两项是贴线达成，probe 勿再收紧）
- `c-master` 的 `minLevel` 已在数据层提前调到 9 与此曲线配套；现行公式下它 6 阶即可做出 92 分，9 阶接单只是稍晚拿到 300 金，无负面

**需要同步修改的既有断言（仅 2 处）**：

1. `tests/unit/round2-economy.test.ts`「ranks seasonal harmony above raw rarity」：春四重奏（碧桃+春兰+玉兰+牡丹）从 95 降为 **86**——玉兰与牡丹色系相邻且无衬花，按新章法本就不该是神品；断言改 `.toBe("fine")`，与 legendaryMixed（65 分）的大小关系仍成立
2. `tests/unit/garden-flows.test.ts`「24 枝花海 = 100」：七系俱全反被判斑杂，新分 **80**；该断言本是对旧公式「溢出瓶口」的注脚，改为 `toBeLessThan(92)` 更符合新语义

其余全部评分相关断言（品第阈值表、退化输入为 0、单调性、神品 <1%、凡品 >5%、雅品 > 精品、上限 <100）在新公式下逐条验证通过，无需改动。
