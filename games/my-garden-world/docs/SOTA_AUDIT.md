# SOTA 审计报告 — 我的花园世界（Round 1 / Fable-1）

参照标尺：Stardew Valley 的操作反馈密度、Cozy Grove / Unpacking 的"juice"（微动效、粒子、声效即时回应）、原作《我的花园世界》的国风手绘氛围。审计对象为 commit `99e0d34` 的 Vite+TS 基线。

---

## 一、缺陷与差距清单（按严重度）

### P0 — 功能性阻断

| # | 缺陷 | 位置 | 说明 |
|---|------|------|------|
| 1 | **花艺作坊完全不可用** | `app.ts` + `ui/panels.ts` | `paint()` 挂在 rAF 上每帧执行，`renderPanel` 每帧 `replaceChildren()` 重建面板。作坊的 `pick` 选材数组是渲染闭包内的局部变量，16ms 后即被清空——玩家永远凑不齐 2-4 枝花材，插花、以及依赖插花的定制订单（`requireScore`）全链路断裂。 |
| 2 | **每帧全量重建 DOM** | `app.ts` | 花园网格、HUD（innerHTML）、面板、教程弹窗全部每帧销毁重建。移动端 touchstart 与 touchend 落在不同节点上导致 click 丢失；GC 压力大、无法维持 60fps 预算；hover/焦点每帧丢失（键盘用户完全无法操作）。 |
| 3 | **订单交付吞花材** | `systems/orders.ts` | 多花材订单逐个 `takeItem`，中途失败直接 return，已扣的花材不退（非事务性）。 |
| 4 | **库存计数错误** | `systems/orders.ts` | 通用订单用 `Object.keys(inventory).length < count` 判断——数的是"种类数"不是"枝数"。持有 3 枝雏菊无法交付"任意 2 枝"订单。 |
| 5 | **通用订单乱扣稀有花** | `systems/orders.ts` | "任意 N 枝"订单按 keys 顺序扣，可能扣走 320 金的星辰郁金香去换 60 金。 |

### P1 — 核心体验缺失（对照原作与任务要求）

| # | 差距 | 说明 |
|---|------|------|
| 6 | **无拖拽浇水** | 教程文案写"拖动洒水壶扫过花圃"，实现是逐格点击。缺少水花粒子与水声反馈。 |
| 7 | **教程无行为门控** | 教程是四连点击的阻断式弹窗，不等待玩家实际完成播种/浇水/收获/交单；弹窗还会遮挡玩家要操作的区域。教程期"订单"步骤可能刷不出雏菊订单，导致新手卡关。 |
| 8 | **定制订单不选作品** | 订单面板交付时盲取 `state.arrangements[0]`，玩家的 95 分精品可能被 70 分订单吞掉，也可能拿不合格的作品去交付而失败。 |
| 9 | **地块视觉是单个字符** | "芽/蕾/花"文字 + 英文 stage 名直接暴露给玩家（`bloom`、`wilt`），无生长动画、无浇水状态可视化、无成熟提示脉冲。 |
| 10 | **光影/时节表现单薄** | 仅换背景渐变 + 夜晚 `saturate(0.85)`。无晨昏过渡、无日月天体、无季节粒子差异（春瓣/夏萤/秋叶/冬雪）、无夜色层。 |
| 11 | **移动端 dock 不可用** | 12 个文字按钮 flex-wrap 成 3+ 行占掉半屏；触达目标 <44px；"重整山河"（清档）无确认直接执行且与常用按钮混排。 |
| 12 | **零无障碍** | 无 aria-label / aria-pressed / role=dialog / aria-live；地块按钮对读屏器只是一个汉字；无 focus-visible 样式；无 prefers-reduced-motion。 |

### P2 — 打磨项

| # | 差距 | 说明 |
|---|------|------|
| 13 | 枯萎收获产生 `inventory[id]=0` 幽灵条目（`addItem(state,id,0)`），污染背包/订单判断。 |

## 二、修复排序（Round 1 已做 ✅ / Round 2 建议 ⏭）

1. ✅ **渲染架构**：细粒度增量渲染——花园每帧只改动变化的节点（进度条宽度、水滴、SVG 仅在 stage 变化时重建）；面板改为脏标记 + 签名比对按需重渲；HUD 逐字段 diff。选材/选作品状态提升到 app 层，不再随渲染丢失。
2. ✅ **订单系统**：`orderReady` 预检 → 事务性扣料；按枝数计数；"任意 N 枝"按最廉价扣；定制订单交付前选择合格作品（默认选"够用的最低分"保护精品）。
3. ✅ **拖拽浇水**：pointer 事件 + `elementFromPoint`，扫过即浇，水花粒子 + 水声，`touch-action:none` 防滚动。
4. ✅ **教程行为门控**：故事节点仍为弹窗，操作节点降级为不遮挡的引导横幅，监听 planted/watered/harvest/orderDone 事件自动推进；dock 按钮随教程进度渐进解锁；教程期保证雏菊订单必然在列。
5. ✅ **地块视觉**：程序化 SVG 花卉（茎/叶/苞/瓣分阶段、按花色渲染、稀有花双层花瓣），水滴计数、施肥标记、成熟脉冲、枯萎灰化、中文阶段名。
6. ✅ **光影时节**：晨/昼/暮/夜四相 + 日月天体 + 星空层 + 季节粒子（春瓣/夏萤/秋叶/冬雪），CSS 过渡实现，零 JS 逐帧成本。
7. ✅ **移动 dock**：工具组/面板组/系统组分区，图章式圆钮（书法字 + 小标签），横向滚动 + safe-area，清档二次确认。
8. ✅ **a11y**：全按钮 aria-label、工具 aria-pressed、弹窗 role=dialog、toast aria-live、地块中文状态朗读、focus-visible、prefers-reduced-motion。
9. ✅(R2) **离线结算**：回归时按真实时长快进生长（封顶 2h）+「欢迎回园」摘要折子，离线不枯萎、订单计时暂停。
10. ⏭ **音景**：环境声层（风/鸟/雨）、浇水白噪声、可持久化的音量设置。
11. ✅(R2) **装扮系统可视化**：12 件装饰各有程序化 SVG 与固定构图席位，落进庭院带（远/中/近三层）。
12. ✅(R2) **花灵形象**：五灵各有场景形象（光晕+灵体+信物），请灵后在花园上空巡游。
13. ⏭(部分 R2) **数值曲线**：订单池已去重（同模板不重复挂出）；订单模板扩充与连续剧情订单仍待做。

## 三、视觉 / UX 圣经（国风手绘向）

**基调**：暖纸底（`--paper #f4e6c8`）+ 墨色（`--ink #2b2118`）+ 点缀朱砂/鎏金/黛玉。夜间整体转靛青纸色。字体：马善政毛笔体做标题章印，思源宋体做正文。

**规则**：

1. **一切操作 ≤150ms 内有三重反馈**：视觉（粒子/缩放）、听觉（chime）、文案（toast）。浇水必有水花，收获必有金瓣迸发，升级必有鎏金脉冲。
2. **状态永远可视**：缺水显示空水滴、可收显示呼吸脉冲、施肥显示星标——玩家不看文字也能读懂每块地。
3. **中文优先**：任何面向玩家的字符串（含阶段名、订单状态）必须是中文；代码内枚举不外泄。
4. **弹窗最少化**：只有故事节点用阻断式弹窗；引导用横幅+目标高亮；确认只用于毁灭性操作（清档）。
5. **触达目标 ≥44×44px**，dock 常驻底部拇指区，safe-area 适配刘海屏。
6. **动效克制**：摇曳 3-4s 周期、缓入缓出；`prefers-reduced-motion` 时全部粒子与摇曳关闭。
7. **昼夜与四季是舞台灯光**：晨曦粉金 → 白昼透亮 → 暮色橙紫 → 夜幕靛蓝+星子；季节决定底色与粒子的种类，两者正交组合。

## 四、性能预算

| 指标 | 预算 | 手段 / 现状 |
|------|------|------|
| 帧率 | 60fps（16.6ms/帧，脚本 ≤4ms） | 每帧仅：时钟推进、12 地块的属性 diff、HUD 字段 diff、倒计时文本。无每帧 DOM 重建、无每帧 innerHTML。粒子全部 CSS 动画（合成器线程）。 |
| 首屏 | 首次可交互 <1.5s（4G）；JS bundle gzip <40KB | 零运行时依赖；程序化 SVG/音频，无图片/音频资源；字体 `display=swap` 不阻塞。 |
| 存档 | 单存档 <8KB（localStorage 5MB 上限的 0.16%） | 纯 JSON 状态，12 地块 + 库存 + 订单 ≈2-4KB；1.5s 节流写入。 |
| DOM | 常驻节点 <400 | 地块 12×~8 节点 + 粒子 ≤24 + HUD/dock ~40。 |
| 内存 | 无泄漏 | 粒子 burst 用 WAAPI `onfinish` 自清理；事件监听集中在 boot 一次注册。 |

## 六、Round 2 增量（Fable-1）

对照 Round 1 简报的遗留清单，本轮吃掉四个头部缺口 + 三处小接线。测试 55 → 78 全绿，tsc strict 全绿。

### 1. 庭院陈设入景（`scene/decor-art.ts` + `garden-view` 庭院带）

装饰不再是一排文字 chip：12 件陈设各有程序化国风 SVG（月洞门/半亭/九曲桥/锦鲤池/青石径/花架秋千/花鸟屏风/纱灯/风铃/铜炉/稻草翁/雪狮），并各占一个**固定构图席位**（x 百分位 + 基准宽 + 远/中/近层）。任意购买顺序落进庭院都是一幅排好的画；新安置有落座弹跳动画。细节：纱灯/铜炉/亭灯入夜自明（`lamp-glow` 由 `.is-night` 点亮并微微闪烁）、风铃三管错拍轻晃、锦鲤慢游——全部 CSS 动画，零逐帧 JS。渲染仍走 `placedDecor` 签名比对，只在变化帧重建。移动端由 `--decor-scale` 统一缩放。庭院对读屏器暴露为一句「庭院陈设：…」。

### 2. 花灵驻园（`scene/spirit-art.ts`）

五灵各有场景形象：光晕（呼吸脉动）+ 灵体 + 各自信物（菊月的花瓣环与新月、池光的涟漪与莲苞、虹蝶的霞色双翼、雪衣的兜帽冰花、岁灯的掌上灯）。请灵后在花园上空 44s 一循环缓缓巡游 + 3.8s 浮沉，落名章随行；换灵/收灵有淡入淡出。同时把一直没接线的 `reputationBonus` 接进 `moodBonus`：驻园花灵按其口碑加成抬高订单赏金倍率（仍封顶 100 口碑），后位灵「功能+口碑」的定位从此成立。

### 3. 花艺品第（`workshop.ts` 评分重做）

旧公式基数 28 + 稀有度总和×6，任意四枝稀有花必满 100，分数毫无层次。新公式：均稀有度×8 + 超两枝每枝+5 + 花色种数×5 + 应季枝数×5 + 和声（全同季+8/两季+4）+ 花器加成；仅 2-4 枝合法。五品分档：凡品(<50)/良品(50)/佳品(70)/精品(85)/神品(95)。数值锚点（有单测钉住）：新手春日双枝 ≈36 凡品；8 阶秋季顶配（彼岸花+枫叶兰+金桂+秋菊，青铜）恰 92，宗师单（≥92）够到但不多给；**满分 100 只有冬雪顶配套**（梦幻玫瑰+雪莲+墨梅+山茶，青铜，冬季）——神品成为全档追求。作坊面板花器预估同步显示品第。

### 4. 离线回归结算（`systems/offline.ts` + 欢迎折子）

原作核心留存机制补齐。规则偏善意：浇够水的生长段按真实时长推进（自动浇水灵可连推至盛放，与池光/岁灯形成协同）；离线**不枯萎**，已盛放的花保留且回归后至少还有 0.9 个花期宽限；订单计时暂停（dueAt 整体顺延，回来不吃口碑惩罚）；水缸按时长回满；生长结算封顶 2h。读档与标签页切回都会结算；教程完成后有实质收获（或离园 ≥3 分钟）时弹「欢迎回园」折子汇报（离园时长/回水/生长段数/盛放名单）。纯函数实现，9 条单测覆盖推进/封顶/宽限/暂停语义。

### 5. 小接线与修缺

- **订单池去重**：挂单不再重复同一模板（模板不足以填满时才允许兜底重复），交付/超时后补位同样去重。
- **老档回填**：`migrate` 按存档等级静默补齐缺失的花种/花灵解锁，且不再因 `unlockedSpirits` 缺失而在开局刷一串「苏醒」吐司。
- **夜色可读性**：夜间令牌挂在 `#app`，但文字色此前继承自 `body`（白日墨色），夜里 HUD 药丸与弹窗都是黑字压黑纸；`.app{color:var(--ink)}` 一行修正（真机夜景截图发现）。

### 6. Round 3 遗留

1. **音景**：仍只有单音 chime；缺环境声层（风/鸟/雨/夜虫）与可持久化音量。
2. **邻居花园**：串门/互赠/参观点赞完全缺失（原作社交留存的另一半）。
3. **内容量**：订单模板 20 条、无连续剧情订单；11 阶后解锁物只剩零星花种。
4. **摆放自由度**：陈设是固定席位，可进阶为拖拽换位/席位二选一；陈列架作品也值得一张图签。
5. **存档节流**：仍是 1.5s 定时整写；可改脏标记 + 关键事件即时写。
6. **老 P2 #17**：缺水时进度条照涨的观感问题仍在（tick 不推进但 `plotProgress` 不看 watered）。
7. **神品引导**：品第/花灵协同/离线机制没有教程后的一次性提示，新玩家难以自发现。
