## 判定规则

每项按现状标 **L0 / L1 / L2**：

| 等级 | 含义 |
| --- | --- |
| L0 | 未实现或形同虚设（不通过） |
| L1 | 功能已落地、可玩，但有口径偏差 / 覆盖缺口 / 登记缺陷（带条件通过） |
| L2 | 达到 SOTA 验收线，无保留（通过） |

整体判级沿用既有口径：**L1 可玩基线 = P0 全部 ≥L1 且其中无 L0 + 自动化链全绿**；**L2 SOTA 达标 = L1 + P1 全部 ≥L1（允许 ≤2 项带条件）**。
「自动化链全绿」的操作口径 = 五条命令退出码 0 且自报 `ok`/`pass` 为 true；契约级缺口（如 probe 缺整回合语义）按对应 TC 项的 L1 缺陷登记，不算命令级红。

> **Round 3 整体判定：L1 可玩基线达成（Round 2 为未达 L1）。未达 L2。**
> P0 22 项全部 ≥L1 且无 L0（L2 8 项 / L1 14 项），自动化链 A1–A5 全绿（含干净环境复跑）。Round 2 阻断 L1 的 5 项 P0 L0（PF-07、TC-01/02/03/06）全部升至 ≥L1。
> 阻断 L2 的是 P1 中的 5 项 L0：PF-11（慢镜终结）、HUD-05（buff/神器图标行）、IN-08（多点触控防误）、TC-07（元素反应单测）、TC-08（羁绊阈值单测），另有 R3-4（effects 指令流消费）这一横切缺陷未决。

### 轴 A · Peggle 手感（PF）

**P0**

- [x] PF-01 `[L1]` 固定步物理 + 渲染插值（O4+O1）
  实况：战斗物理已切上游——`core/sim.js` 成为 `src/physics` 的游戏侧适配层（实体镜像 + 事件翻译），`stepWorld` 用真固定步累加器（`_accum`，步长恒 1/120，单帧上限 8 步），上游积分器禁 `Math.random`。Round 2 的「子步长随帧长变化」问题已消除。
  缺陷：上游已提供 `prevX/prevY` + `renderPosition(alpha)`，但渲染层未消费插值（`ui/render.js` 直接画 `egg.x/y`；120Hz 步频下肉眼影响小）。
- [x] PF-02 `[L1]` 反弹方向正确、动能不增（O1）
  实况：在用积分器 `reflect` 恒 e<1（游戏侧表面弹性经 `surface()` 折算后合成弹性 ≤0.92）+ 切向摩擦；F4 五角度全场景对拍中 293 个飞行点无一加速异常。
  缺陷：动能不增仍无显式单测断言（TC-01 遗留项）。
- [x] PF-03 `[L1]` 无隧穿（O1）
  实况：速度自适应子步（`SUBSTEP_TRAVEL_RATIO` + `MAX_SUBSTEPS`）+ 扫掠式碰撞（`collideCircleBody` 带 from 位置）+ `MAX_EGG_SPEED=1900` 钳制，2px 薄段有效半径 r+厚度/2。

- [x] PF-04 `[L2]` 拖拽瞄准 ±70°、初速 220–720（O4）：`MAX_AIM_DEG=70`、`MIN/MAX_SPEED=220/720`，`setAim` 与 UI 双重钳制，契约 v1.1 §35 定稿一致。
- [x] PF-05 `[L2 ↑R2:L1]` 预测线与实弹同源、ε≤0.5px（O1+O4）
  实况：预测幽灵蛋与实弹经由**同一个** `physics.advanceEgg`（「任何一方要改积分顺序都必须改这一个函数」），预步力 `prepareEgg`（冰面阻力/追踪）两路径共用。仓内新增在用适配层对拍测试（24 步端点误差 <1e-10）；F4 独立验证：5 个瞄准角 × 全场景（钉/砖/钢砖/斜面/敌人），293 个飞行段预测点与实弹逐位相等（ε=0）。
  备注（不扣级）：实弹在 y>820 回收后，预测线会多画 1 个越过回收线的尾点（本次实测最大越出 13.7px），位置在 800px 画布之外、玩家不可见；已登记为低优先视觉项（§四.8）。
- [x] PF-06 `[L2 ↑R2:L1]` 回收判定（O1）
  实况：口径已裁决——物理层出界 y>820（契约 v1.1 `OUT_MARGIN_BOTTOM=20` 定稿，且在用实现有测试覆盖）+ 睡眠 + 寿命三层兜底；游戏层再叠停滞回收（<45px/s 持续 0.6s，`core/sim.js` 注明是防磨蹭的游戏策略，物理 8px/s 睡眠阈值仍在）。实玩无卡回合。
- [x] PF-07 `[L1 ↑R2:L0]` 确定性（O1+O4）
  实况：固定步 + 物理层禁 `Math.random`（世界内随机走 `world.rngState` mulberry32）+ 战斗 RNG 种子化（`hashSeed(config.seed ?? level.id)`）。F4 实测：同布局双蛋（含蛋-蛋碰撞）1200 固定步跑两遍，2108 个位置/速度采样逐位一致，`world.stats` 一致。
  缺陷：① `core/bestiary.js` 的 `makeEnemy` 用 `Math.random` 生成 `driftPhase` 与敌人 id——含漂移敌（如 `pigeon`，drift=42）的关卡敌人运动逐局不同，同种子不可逐位复现；② `heroes/triggers.js` 在 ctx 缺 rng 时兜底 `Math.random`；③ 仓内无 1200 步一致性回归测试（F4 脚本未入仓）。
