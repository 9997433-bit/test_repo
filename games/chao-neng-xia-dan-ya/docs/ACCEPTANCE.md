# 超能下蛋鸭 · 验收标准与步骤（Round 2 重评）

- 所有者：F4 SOTA 验收 · `claude-fable-5-thinking-xhigh`（本文件与 `SOTA_CHECKLIST.md` 独占写入）
- 适用范围：`games/chao-neng-xia-dan-ya/` 全部交付；逐项 ID、L0/L1/L2 打分与缺陷登记见 `SOTA_CHECKLIST.md`
- 判定等级：L0 未达可玩基线 / L1 可玩基线（P0 全部 ≥L1 且无 L0 + §1 全绿）/ L2 SOTA 达标（+P1 全部 ≥L1，带条件 ≤2）/ L3 精品加分（+P2 ≥60%）

## 判定总则

1. 每项按 `SOTA_CHECKLIST.md` 的 ID 给出 **L0 / L1 / L2**（等价于不通过 / 带条件通过 / 通过）。L1 必须登记缺陷与责任人。
2. 自动化链（§1）是硬门槛：任何一步红即整轮判 L1 失败，无论手动体验多好。
3. 数值口径以 `.agent_workspace/GDD.md` 为准；GDD 与实现冲突时，先改其一并同步单测，再验收（禁止「实现即标准」）。Round 2 已登记三处冲突：连击倍率、回收阈值、震屏幅度（见 `SOTA_CHECKLIST.md` §四）。
4. 验收人不得修改实现代码；发现问题只登记缺陷并指派所有者。本轮登记的实装缺陷：暂停中 Esc 叠开弹窗（IN-07）、多点触控抢瞄准（IN-08）、`resolveHit` effects/comboDelta 未消费（R3-4）。
5. **测试必须对准在用实现**：断言写在未接线模块上（如当前 TC-01 断言 `src/physics` 而战斗跑 `core/sim.js`）不计入对应 TC 项的通过证据。

## 2. 手动验收脚本（M 系列）

前置：`npm run dev`，打开 `http://localhost:4174`，桌面 Chrome 最新版。每个脚本按步骤顺序执行，任一步不满足期望即该步关联 ID 判不通过。
（M1–M6 步骤与 Round 1 版本一致，为 Round 3 复验与录屏取证的执行底稿，此处保留全文。）

### M1 · Peggle 手感（PF-01…07、PF-10/11）

1. 进入冒险第 1 关，按住拖拽瞄准：出现虚线弹道，且显示 ≥3 次反弹预览（PF-05）。
2. 左右拖到极限：瞄准角被钳制在 ±70°，无越界（PF-04）。
3. 缓慢小幅拖动：角度以小增量变化，可精确对准单个钉（PF-10）。
4. 松开发射：蛋沿预测虚线飞行，前 3 次反弹与虚线目测重合，无肉眼可见偏离（PF-05）。
5. 观察蛋撞墙 / 钉 / 斜面：反弹方向符合入射角，多次反弹后不加速（PF-02）。
6. 全力蓄力朝薄砖边缘连发 10 次：蛋不穿墙、不卡进静态体内部（PF-03）。
7. 蛋落底或静止：0.6s 内回收并进入下一回合，无卡死（PF-06）。
8. 击杀本关最后一敌：出现慢镜头终结演出（PF-11，P1）。

### M2 · 肉鸽 HUD（HUD-01…09）

1. 战斗中确认常显：生命、当前英雄 + 能量条、连击层数、波次进度，四者齐全且 1 秒内可读（HUD-01）。
2. 命中敌人：飘字出现；打出暴击与元素伤害，三种飘字肉眼可区分且不遮瞄准线（HUD-02）。
3. 通关：结算屏显示金币 / 碎片与评分四项（连击峰值、用时、剩余生命、清扫率）（HUD-03）。
4. 进入肉鸽模式打满 2 波：弹出三选一，卡面含流派 tag 与羁绊预览（HUD-04）。
5. 选中神器后：HUD 图标行出现该神器，悬停出 tooltip（HUD-05）；羁绊面板对应流派点亮（HUD-06）。
6. 对敌施加灼烧与冻结：敌人头顶出现形状不同的状态图标（灰度截图仍可分辨）（HUD-07）。
7. 故意送掉本局：死亡回顾显示波次 / 总伤 / 构筑；再进一次确认本地排行留存（HUD-08）。
8. 打到 BOSS 波：出现预警横幅与 BOSS 血条（HUD-09）。

### M3 · JUICE（JC-01…09）

1. 首次点击页面后发射：能听到发射音与命中音，控制台无 AudioContext 报错（JC-01/02）。
2. 命中敌人瞬间：目标闪白、画面停顿约 30ms（逐帧录屏核对 ≥1 帧停滞）（JC-01/03）。
3. 爆炸 / 重击时：屏幕轻震且 150ms 内回稳；在设置中关闭震屏后重试，无震动（JC-04）。
4. 命中与碎砖：蛋液 / 碎片粒子出现，粒子风暴中帧率不跌破 §3 口径（JC-05）。
5. 连续命中叠连击：音效逐层升调，断连后回落基音（JC-06）。
6. 观察飞行中的蛋：有轨迹残影（JC-07）。
7. 设置 `reduceMotion` 开：震屏 / 粒子 / 残影关闭，飘字与闪白保留（JC-08）。
8. 能量满后按 `Q`：大招全屏演出 + 专属音（JC-09）。

### M4 · 触控（IN-01/02/04/06/08）

前置：devtools 设备模拟（iPhone SE 375×667 与 360px 窄屏各一轮）；有条件补一轮真机。

1. 在画布上滑动瞄准：页面不滚动、不缩放、地址栏不弹跳（IN-01）。
2. 完整触摸打一关：滑动瞄准 → 松开发射 → 点按大招 → 点按暂停，全程无需键鼠（IN-02）。
3. 360px 宽下检查：画布等比缩放无拉伸变形，HUD 无重叠裁切（IN-04）。
4. 用 devtools 测量按钮与三选一卡片：命中区 ≥44×44 CSS px（IN-06）。
5. 瞄准中第二指点击画布另一处：不触发二次发射、当前瞄准不被打断（IN-08）。

### M5 · 键盘（IN-03/05/07）

1. 全程不碰鼠标：`1–5` 切英雄、空格蓄力发射、`Q` 大招、`R` 重瞄、`Esc` 暂停均生效（IN-03）。
2. `←/→` 调角，按住有加速度；纯键盘通关教程关（IN-05）。
3. `Esc` 打开暂停菜单后 Tab 巡航：焦点可见、可循环、无陷阱，`Esc` 可退出（IN-07）。

### M6 · 性能（60fps 目标）

1. devtools Performance 录制 30s「连击风暴」场景（多蛋分裂 + 粒子 + 飘字齐发）。
2. 通过标准：平均 ≥58fps，1% 低帧 ≥45fps，无单个 >100ms 长任务；`npm run bench` 的 A3 口径同时通过。
3. 记录环境：CPU 型号 / 是否降频模拟（如用 4× CPU throttle 作移动端代理，单独记录一行结果）。

## 4. 回归守则

1. 物理常量（重力 / 步长 / 弹性 / 初速范围 / 回收阈值）变更必须同轮更新 GDD、单测与本文件口径，三者不一致判红。
2. 任何 P0 项等级下降（L2→L1、L1→L0）即视为回归，阻断合并，责任所有者本轮内修复。
3. 共享文件（`package.json` / `vite.config.js` / `README.md` / `index.html`）只追加；新增 npm script 必须在本文件 §1 登记验收标准。
4. 性能口径只认 TC-05 与 M6；Round 1 空转 bench 数值（13554 steps/ms 等）永久禁用；Round 2 起基准必须标注被测积分器（在用 / 上游）。
5. 单测/probe/bench 的被测对象必须与战斗在用实现一致（总则 5），「测 A 用 B」不计入通过证据。
