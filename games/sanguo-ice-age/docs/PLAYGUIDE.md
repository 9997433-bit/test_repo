# 玩家指南（PLAYGUIDE）

> 本指南与代码实态对齐（`js/main.js` 走 systems + bridge 正常路径，存档统一走 `engine/save.js`）。
> 数值口径以 `js/config.js`、`js/data/buildings.js`、`js/bridge/actions.js` 为准。

---

## 1. 如何运行

游戏是纯前端 ES Modules 工程，没有构建步骤，也没有任何 npm 运行时依赖。
但 `file://` 直接打开会被浏览器的模块加载策略拦截，必须走 HTTP：

```bash
cd games/sanguo-ice-age
python3 -m http.server 4176 --bind 127.0.0.1   # 等价于 npm start
```

浏览器访问 `http://127.0.0.1:4176/`。

- 首次进入自动播放新手引导；任意时刻按 `H` 重看。
- 控制台会打印一行装配信息，正常应包含 `systems 接管：climate → city → economy → population → quests`。
  若看到「最小内核」字样，说明某个核心模块加载失败，此时只能看城 / 派工 / 升级，招募与讨伐不可用。

## 2. 如何测试

需要 Node.js（仅测试脚本使用）：

| 命令 | npm script | 说明 |
|---|---|---|
| `node tests/runner.mjs` | `npm test` | 单元 + 集成测试，24 个用例（经济 / 气候 / 战斗 / 存档 / 任务 / 桥接投影 / 十连 tick 集成），当前全部通过 |
| `node tests/bench.mjs` | `npm run bench` | 性能基准，输出各系统 tick 耗时 |
| `node tests/probes.mjs` | `npm run probe` | 冒烟探针，输出 JSON 报告（含坏档容错等场景） |

手工调试入口：页面加载后全局暴露 `window.__sanguo`，可访问 `engine`（`.raw` 为权威状态、`.view()` 为投影）、`renderer`、`applySpeed(n)`、`restart()` 等。

## 3. 时间与节奏

- 1 倍速下每 250ms 一个逻辑 tick（`TICK_MS`），16 tick 为一天（`TICKS_PER_DAY`），即一天约 4 秒。
- 倍速档位 1x / 2x / 4x；暂停时画面仍保留微弱雪与火焰动态。
- 每 8 秒自动存档一次，关闭页面前也会存一次。

## 4. 核心循环

### 4.1 火炉与燃料

- 火炉每级供热 **3.2°**；每 tick 每级烧 **0.08 木** 或 **0.035 煤**（寒潮期间消耗 ×1.4）。
- 火炉面板可切换燃料策略：**自动**（寒潮烧煤、平时省煤烧柴）/ **木柴** / **石炭**。
- 燃料烧尽即熄火，全城温度骤降——底栏火炉按钮会在燃料不足 2 日时闪烁告警。
- **火炉等级是其他建筑的等级上限**；而火炉升级又要求特定建筑先达标（如升 2 级前伐木场、猎人小屋须达 1 级），形成「炉—矿」交替升级的主节奏。

### 4.2 气候与寒潮

- 基础温度 4°，随天数缓慢走低；约每 **7 天**一次寒潮，降温 **−14°** 上下、持续约 **2 天**，且一场比一场更烈（烈度逐场 +0.06）。
- 温度分带：≤−6° 冰封（民心流失快）、≤0° 严寒、≥8° 温暖（民心回升）。天气条会预告「x 日后寒潮」。
- 民居 / 厨房 / 诊所等建筑提供每级保温加成，可部分抵消寒潮。

### 4.3 经济与人口

- 建筑产出 = 每级基础产量 × 工人在岗系数 × 民心系数 × 气候系数（× 武将驻守系数）。
- 资源有仓储上限（火炉与仓库提供容量），满仓溢出直接浪费。
- 民居决定人口上限；人口消耗口粮，断粮急速拉低民心。
- **败亡条件**：民心 ≤15（`morale`）或人口归零（`extinct`）。没有胜利结局，活得越久越好。

### 4.4 武将与招募

- 招贤馆（tavern）用招募令抽将：**120 肉食 + 60 精铁**一张，开局赠 3 张。
- 十连保底：前九抽全蓝时末抽必出紫以上。品质从低到高 blue / purple / orange / red。
- 同阵营（魏 / 蜀 / 吴 / 群）≥3 人出战有攻击加成。
- 开局自带刘备、张飞、华佗；主线任务《初雪扬威》奖励赵云。
- 招募与战斗的随机数来自存档种子（`meta.seed`）派生的独立随机流，游标随存档保存——同一份存档重放结果一致，读档刷抽卡无效。

### 4.5 练兵与讨伐

- 兵营派驻工人即持续练兵（消耗粮 / 木 / 铁）；兵力上限 = 20 + 12 × 各兵营等级之和。
- 讨伐面板列 5 档流寇（t1 / t2 / t3 / t5 / t8，同一存档同档位敌情固定），出征需 **至少 1 名武将 + 10 名士兵**。
- 克制关系：兵种 **步克骑、骑克弓、弓克步**；阵营 **吴克蜀、蜀克魏、魏克吴**。民心也计入攻击乘区。
- 胜：得物资 / 招募令 / 武将经验，民心 +5；败：折兵、民心 −4。部分损兵转入伤兵，由诊所逐日康复。

### 4.6 太学典籍（书院）

| 典籍 | 需书院等级 | 造价 | 效果 |
|---|---|---|---|
| 御寒夯土 | 1 | 180 木 + 60 铁 | 全城温度 +1.5° |
| 精钢利斧 | 1 | 150 木 + 90 铁 | 木材产出 +20% |
| 腌藏之法 | 2 | 220 粮 + 120 铁 | 肉食产出 +20% |
| 深层煤脉 | 2 | 260 木 + 160 铁 | 煤炭产出 +25% |
| 屯田练兵 | 3 | 320 粮 + 240 铁 | 征募速度 +30% |
| 经世致用 | 3 | 340 木 + 280 铁 | 民心恢复 +30% |

### 4.7 功业簿（主线任务，12 条）

伐木积薪（伐木场 1 级）→ 雪原猎粮（猎人小屋 1 级）→ 炉火御寒（火炉 2 级）→ 收容流民（民居 2 级）→ 凿煤备寒（煤矿 2 级）→ 炉旺城兴（火炉 3 级）→ 筑馆招贤（招贤馆 1 级）→ 豪杰来投（招募 1 名武将）→ 整军经武（步兵营 1 级）→ 厉兵秣马（练兵 20 名）→ 初雪扬威（打赢一仗，奖励赵云）→ 炉暖山河（火炉 5 级）。

任务达成后停在「可领取」，在左上托盘或「全部 →」打开的功业簿面板点**领赏**入账（物资 / 招募令 / 武将经验 / 武将）。

## 7. 存档

- 单键 localStorage：`sanguo-ice-age-save-v1`（`SAVE_VERSION = 1`），信封 `{ format, version, savedAt, state }`。
- 每 8 秒 + 页面关闭前自动保存；隐私模式下自动退回内存存储（刷新即失）。
- **导出 / 导入**：顶栏「导出」把当前局面下载为 JSON 文件；「导入」从文件载入（结构不合法时保持当前局面不变）。失败幕上也可导出败局存档留存。
- 读档经 `normalizeState` 补齐 + `assertState` 校验，任一校验不过整档按新游戏处理。
- 重开一局：败亡后按 `N` 或点失败幕「东山再起」，也可用控制台 `window.__sanguo.restart()`。

## 8. 已知限制

以下均据当前代码核实：

1. **四种建筑 UI 不可达**：`bridge/view.js` 的 `LAYOUT_KEYS` 只映射了 13 个建筑，弓兵营（`barracks_arch`）、骑兵营（`barracks_cav`）、伤兵营（`hospital`）、使馆（`embassy`）不在其中——画布不绘制、无法点击、无法营建（画布美术 `render/canvas.js TILES` 其实已备好这四个地块）。连带影响：实际只能练步兵；伤兵康复只靠诊所；使馆本身也没有机制实现。
2. **无胜利结局**：`flags.victory` 恒为 false，无任何代码置真；功业簿走完后进入无尽生存。
3. **武将驻守无 UI**：驻守加成（`garrisonBuildingId`、`economy.garrisonFactor`）有完整数值通道，但没有任何面板可以指派武将驻守。
4. **坏档不备份、旧档不迁移**：读档校验失败直接按新游戏处理，不会另存备份（localStorage 里原始数据仍在，可手动复制该键留存）；合并前旧版内核的扁平存档（键 `sanguo-ice-age-save-v1-ui`）已不再读取，也没有迁移器。
5. **随机流边界偏差**：`engine/rng.js` 的 `setState(v)` 内部走 `hashSeed`，游标恰为 0 时会被映成 1。招募 / 战斗游标实际从非零起步，正常游玩不受影响，属于断点续随机的边界瑕疵。
6. **降级内核功能有限**：任一核心模块（`state.js` / `systems/city.js` / bridge）加载失败时回落内置最小内核，只保证不白屏：能看城、派工、升级，招募 / 讨伐 / 典籍 / 任务 / 导入导出均不可用，并在邸报提示「核心模块未就绪」。
