## 1. 对标基准拆解

### 1.1 Frostpunk：生存压力必须**一屏可读**

Frostpunk 的核心不是数值难，而是玩家任何时刻扫一眼屏幕就知道三件事：
**现在多冷、还能撑多久、下一个坏消息什么时候来。** 落到本作：

| Frostpunk 要素 | 本作对应物 | 现状 |
|---|---|---|
| 温度计是世界的主角 | HUD 中央温度计（汞柱 + 档位文案 + 冻结变色） | ✅ 已有，缺「距冻结还差 N°」微文案与趋势箭头 |
| 热区可视（家家户户的温度圈） | 火炉暖光半径随等级扩大、熄火只剩青烟 | ✅ 光晕已随 level/lit 变化 |
| 倒计时式恐惧（风暴将至） | 天气条「N 日后寒潮」+ 寒潮横幅 + 全屏结霜 | ✅ 骨架齐全，缺寒潮**前夜**的升级紧迫感引导 |
| 资源余量换算成「还能活几天」 | 火炉面板「燃料可支 N 日」 | ✅ 有，但只在面板内，未常驻 HUD |
| 失败近在咫尺（不满/希望双表） | 民心条 + 崩溃线 15 | ❌ **民心跌穿只发日志，游戏不会输**——张力的地基缺失 |

### 1.2 三国 SLG：每一次投入都要有**即时、具体、可炫耀**的回报

率土/三战类的养成爽感三定律：抽卡要有仪式感、数值成长要可见（战力跳字）、克制要能被学会（战报教学）。

| SLG 要素 | 本作对应物 | 现状 |
|---|---|---|
| 抽卡开箱仪式 | 十连翻牌逐张入场（70ms stagger）、品质色框、保底紫 | ✅ 有基础版；缺橙/红将的全屏高光时刻 |
| 战力数字与羁绊 | 武将卡战力、同阵营 2/3 人 +8%/+18% 提示 | ✅ 有；羁绊只在文案，未做「即将凑齐」的诱导 |
| 克制教学 | 出征前胜算注记 + 战报「（克制）」标 | ✅ 有；缺乘区数值外显（+25% 写出来） |
| 养成多线（等级/星级/驻防） | UI 只有「重复=升级」单线；星级/碎片/驻防在 systems 侧睡觉 | 🟡 深度已写好，未上桌 |
| 目标牵引（任务链/成就） | 12 条主线任务链（数据+逻辑全有、单测通过） | ⬜ **无任何 UI 入口**，玩家感知不到目标 |

### 1.3 Juice：状态变化必须被「看到、听到、感到」

好手感 = 每个状态变化配一个 ≤600ms 的物理反馈。本作已有底子（升级建筑脉冲 `renderer.pulse`、toast、横幅、结霜遮罩、雪粒子三层、村民通勤），缺的是把反馈接到**每一个**关键事件上，并控制不过载。

## 2. 十二条打磨线

> 顺序即建议优先级。每条 = 目标 ／ 现状 ／ 差距动作 ／ 验收锚点。

**① 温度即命脉的一屏可读**
目标：不看数字也知道处境——温度计做主视觉，配「距冻结 N°」微文案与升/降趋势箭头，全局色调随温度带插值。
现状：温度计 + 档位文案 + 冻结变色已有；场景色调随寒潮变化已有。
差距：加趋势箭头与冻结差值；freeze 档位时 HUD 描边结霜（tokens.css 已备 `--border-frost` 类变量）。
锚点：P0-07。
R2 复核：**未动，且差距比 Round 1 记载更大**——tokens.css §7 的 `html[data-temp]` / `html[data-crisis]`
整套主题层（`--temp-readout`/`--clime-veil`/`--hud-edge`/崩溃去饱和/寒潮三闪）是**孤儿 CSS**：
全 `js/` 无一处写 `documentElement.dataset`，HUD 只在 `#vital-temp` 上切局部类 `is-freeze`/`is-warm`。
已列为 §2b 硬性第 4 项。

**② 寒潮节拍的恐惧曲线**
目标：预警（前 1 天）→ 压迫（倒计时变红脉冲）→ 爆发（横幅+闪屏 0.5s）→ 释放（潮退日志+色调回暖），四拍齐全。
现状：倒计时、横幅、结霜、潮退日志齐；缺「倒计时 ≤1 天」的红色脉冲与潮退的视觉回暖瞬间。
差距：倒计时告警态；寒潮烈度逐场递增（systems 已实现）接入后，横幅需展示烈度让玩家感知螺旋升级。
锚点：P0-06、B-02。
R2 复核：未动。注意 `--anim-danger-flash`（WCAG 合规三闪）与 `data-crisis="blizzard"` 红晕罩已在
tokens.css 备好但从未被触发——接活 §2b 第 4 项后，本条的「压迫拍」几乎零成本。

**③ 燃料焦虑常驻化**
目标：「还能烧几天」是 Frostpunk 式核心焦虑，必须常驻 HUD 而非藏在面板里。
现状：dock 火炉按钮有「燃料 N 日」小字 + <2 日脉冲；面板内有完整数据。
差距：断供前 30s 级别的强提醒（toast + 温度计闪烁）；熄火瞬间给一次全屏暗场 0.3s——现在熄火只有日志，情绪价值为零。
锚点：P0-05。
R2 复核：未动（`main.js` 熄火路径仍只有 `log("燃料告罄…")`）。列为 §2b 缓冲第 7 项。

**④ 资源流的因果可读**
目标：每个数字旁边都答得出「为什么在变」。净增/日已有，需补：悬浮资源出分解 tooltip（产出−口粮−燃料−练兵）、<1 天见底时下划线告警。
现状：净增/日、储量条、满仓/低量变色齐全；分解 tooltip 无。
差距：economy 系统的 `production/upkeep/perDay` 分解数据已算好（🟡 未接 UI），统一后直接喂 tooltip。
锚点：P0-11、P1-01。
R2 复核（基线）：未动。依赖桥接/投影层（施工树已在做 `js/bridge/view.js` 的 `projectView`，见 §3 施工动态）。

**⑤ 升级的前因后果对照**
目标：所有升级按钮都能回答「花什么、得什么、为什么不能点」。
现状：now→next 产出对照、缺口资源标红、封顶原因文案——这块是当前 UI 最强的部分，保持。
差距：升火炉的「反向前置」（systems `furnacePrereqFor`：先把伐木场升到 N-1 才能升火炉 N）接入后，缺失前置要列清单，不能只说「不可升级」。
锚点：P0-08、P0-09。
R2 复核：未动（UI 侧保持强项，systems 反向前置仍未上桌）。`canUpgrade` 的返回结构
`{ok,reason,text,missing[]}` 已可直接喂 UI，接入成本低。

**⑥ 派工的手感**
目标：加减工人像拨算盘：pip 点阵即时亮灭、产出数字同帧跳动、闲置丁口徽章同步。
现状：pip、闲置数、上限禁用全有。
差距：人口冻损导致的自动撤工目前无感知——需要一条「N 名工人冻伤离岗」toast + 建筑图标短暂变灰，否则玩家只觉得产量莫名下降。
锚点：P0-10、B-07。
R2 复核：未动。列为 §2b 缓冲第 8 项。

**⑦ 招贤的仪式感升级**
目标：橙/红将出货 = 全屏时刻（绸带横幅 + 停顿 0.4s + 卡面高光扫过）；十连保底进度可视化。
现状：翻牌 stagger、品质色、重复转化文案已有；橙红将只多一条日志。
差距：出货高光；把「十连必出紫」写在按钮旁而非说明段落里；systems 的星级/碎片系统接入后，重复获得要有「星级 +1」的爆点动画。
锚点：P0-15。
R2 复核：未动。列为 §2b 缓冲第 9 项。

**⑧ 战报的叙事与教学**
目标：战报是克制系统的教科书：每回合伤害数字外显克制乘区（「斩敌 1840（骑克弓 +25%）」）、胜负原因一句话总结。
现状：逐回合中文文案、克制标注、缴获/阵亡清单已有，质感不错。
差距：乘区数值化；接入 systems/combat 后回合是真实结算而非纯演出，技能触发事件（`rollSkills` 已产出事件流）要变成战报里的高光行。
锚点：P0-16、P0-17、P1-04。
R2 复核：未动，且要警惕**两套克制数值并存**：UI 内核胜算加成用 +0.12/+0.10，systems 伤害乘区是
1.25/1.15（有单测钉死）。战报外显数字时必须以 systems 乘区为准，否则教学教错。§2b 硬性第 3 项。

**⑨ 养成反馈闭环**
目标：武将升级瞬间战力数字滚动上跳 + 卡面微弹；同阵营「差 1 人凑羁绊」的提示常驻招贤面板，驱动下一次抽卡。
现状：战力展示齐全，变化无动画；羁绊只有静态说明。
差距：数字滚动（UX.md 已规定 300ms 数字滚动规范，未实现）；「蜀 ×2，再得 1 名蜀将 +18%」这类临门一脚提示。
锚点：P0-15、P1-07。
R2 复核：未动。列为 §2b 缓冲第 10 项。

**⑩ 任务链 = 隐形教程 + 目标牵引**
目标：屏幕上永远有一个「下一步该干嘛」——data/quests.js 的 12 条链就是为此设计的（奖励刻意前置：寒潮前推火炉 2 级并补煤）。
现状：逻辑与数据全部就绪且有单测，**玩家完全看不到**。
差距：一个侧边任务托盘（当前任务 + 进度条 + 领取红点）就能把留存曲线立起来；这是**性价比最高的一条线**。
锚点：P1-03。

`q_sawmill_3` 引用不存在 id `sawmill` 的坑仍在（精确位置：`systems/quests.js` 内置链，非 `data/quests.js`，
后者用的是规范 id `lumber`）。§2b 硬性第 1 项；施工树中已见 `#quest-tray`「功业簿」托盘雏形。

R2 复核：未动。本轮新增动效（失败幕、抽卡高光、寒潮脉冲）落地时须按本条预算自查，别新增各闪各的源。

## 2b. Round 2 必补视觉/反馈差距（复核后新增，前五项为硬性交付）

> 判定标准回到三个坐标系：**Frostpunk 可读性**（世界状态一屏可读、失败近在咫尺）、
> **三国 SLG 反馈**（目标牵引、克制可学会、进度可炫耀）、**Juice**（状态变化必须被看到）。
> 每项给出：坐标系归属 ／ 现状证据（基线 27bfac5 实测）／ 做法要点 ／ 验收锚点 ／ 施工树观察。
> 「施工树观察」= 复核时在未提交工作树中看到的雏形，**不等于完成**——验收以提交后按锚点条款复测为准。

**【硬性 1】任务托盘** —— SLG 反馈·目标牵引（打磨线⑩）
证据：`systems/quests` + `data/quests.js` 12 条链有单测、id 已规范化，但 `main.js` import 后零引用，屏幕上无任何任务元素。
做法：侧栏常驻托盘（当前任务标题 + 进度条 + 可领取红点 + 领奖 toast）；`initQuests/tickQuests/claimQuest` 三个函数即全部依赖。
锚点：P1-03。**这是全项目性价比最高的一笔**：留存曲线 + 隐形教程一次到位。
施工树观察：`index.html` 已见 `#quest-tray`「功业簿」托盘（含计数徽章与「全部 →」入口），hud.js 有任务列表读取逻辑。复测点：领奖入账、红点、`q_main_11` 赠赵云链路。

**【硬性 2】失败幕（含胜利幕骨架）** —— Frostpunk 可读性·失败近在咫尺（§3 差距二）
证据：UI 内核 `S.population.total = Math.max(1, …)` 把人口下限写死为 1，民心 <15 只发一条日志；
systems 侧 `flags.gameOver="morale"/"extinct"` 已实现且有探针，无人消费；`data-crisis="collapse"` 的去饱和死寂视效在 CSS 里睡觉。
做法：判定触发 → 模拟停止 → 全屏结算幕（存活天数、终局 stats、死因一句话、重开按钮），入场配 `data-crisis="collapse"`。
锚点：P0-13、P0-14。没有这一项，其余全部生存打磨都是装修没有地基。
施工树观察：`main.js`/`hud.js` 已见 gameOver 消费与「东山再起」重开、`#btn-gameover-export` 结算幕导出按钮。复测点：判定触发后模拟真的停止、人口下限 1 的旧逻辑被移除、民心红线与 DESIGN「连续 2 天」的裁决写明。

**【硬性 3】战报克制数字外显** —— SLG 反馈·克制可学会（打磨线⑧）
证据：战报只有「（克制）」二字标注（`main.js` 回合行）；预览注记只有「某某 阵营克制」无数值。
且 UI 与 systems 数值不一致：UI 胜算加成 +0.12/+0.10，systems 伤害乘区 1.25/1.15（单测钉死 25%）。
做法：伤害行写成「斩敌 1840（骑克弓 +25%）」，数值**以 systems 乘区为准**；预览注记同步带 ±%。
锚点：P0-17、P1-04。
施工树观察：`panels.js` 已见「克制乘区」区块与 troopAdvantage/factionAdvantage 字段。复测点：外显数值与 `systems/combat` 单测钉死的 1.25/1.15 一致，方向与 `FACTION_BEATS`/`TROOP_BEATS` 相符。

**【硬性 4】温度色随 `data-temp`** —— Frostpunk 可读性·一屏可读（打磨线①②）
证据：tokens.css §7 已写好 `html[data-temp="comfort|mild|cold|freeze"]` 与 `html[data-crisis="blizzard|collapse"]`
两组主题（读数变色、HUD 结霜描边、冷雾/暖晖罩、寒潮三闪、崩溃去饱和），但全 `js/` 无一处写
`documentElement.dataset.temp/crisis` —— 整层是孤儿 CSS。
做法：HUD update 内按温度带与危机态写两个 dataset 属性（约 5 行），全屏氛围立刻激活；顺手把打磨线②的
寒潮压迫拍（`--anim-danger-flash`）接上。**本轮投入产出比仅次于任务托盘。**
锚点：P0-06、P0-07。
施工树观察：`hud.js` 已见 `documentElement.dataset.temp/crisis` 写入（含去抖判断）。复测点：四档 band 与温度计档位文案同帧一致、危机态退出时 dataset 被清除、`prefers-reduced-motion` 下三闪被禁用。

**【硬性 5】存档导入导出按钮** —— 玩家资产安全感 + 测试载体
证据：`engine/save.js` 的 `exportSave/importSave`（信封 + `assertState` 校验 + 中文报错）有单测，
但 UI 无系统面板、无任何按钮；玩家资产只活在一个 localStorage 键里。
做法：dock 或角落加「系统」入口：导出（下载 JSON，文件名含天数）＋ 粘贴/选文件导入（坏档弹明确错误、不影响当前局）。

## 3. 当前最大验收差距（按伤害排序）

### 差距一：双内核断层——引擎的「里子」和游戏的「面子」互不认识

这是压倒其余一切的结构性差距（详见 `ACCEPTANCE.md` §1.1）：

- 玩家玩到的是 `main.js` 里的应急内核（FALLBACK CORE，约 850 行）：瞬发升级、标量兵力、`Math.random` 掷骰、永不失败；
- 而真正达到 SOTA 水准的系统——施工工期、三兵种确定性战斗、疾病/伤兵、任务链、星级养成、正规存档校验、可复现 RNG——全部躺在 `js/systems/*` 里**只被测试消费**。
- `npm test` 的那颗红灯（`quests/production` 门槛探针）就是这个断层的机读证据：探针拿扁平 state 问
  `city.canUpgrade`，实现只认嵌套 state。**R2 复核确认基线红灯仍在**（worktree 检出 27bfac5 实测 15/1/2）。

**R2 施工动态（未提交，最终以提交后复测为准）**：Round 2 实现者已沿本建议动工——工作树中出现
`js/bridge/view.js`（`projectView` 投影层）与 `js/bridge/actions.js`，探针改为嵌套形状、新增
`bridge-project-view` 收敛探针与 integration 套件，施工树测试 22/22 绿。
**验收警戒**：转绿必须来自「断层真正收敛」（`bridge.active === true`、控制台不再打印
「状态结构与 UI 内核不同」），而不是仅仅把探针形状改得和实现一致——复测时两条都要看。

**后果**：游戏的深度上限被锁死在应急内核；且两套数值（抽卡概率、寒潮模型、克制加成、开局资源）会持续发散，越晚统一代价越大。
**收敛建议**：裁决嵌套 `state.js` 为唯一事实源；`main.js` 的 `view()` 改为从嵌套 state 派生的只读投影层（工作树中的 `js/bridge/view.js` `projectView` 即此物），UI 面板全部改走 systems 的 action 函数（`js/bridge/actions.js`）。
（施工树中另见 `config.js` 升级为 16 个权威建筑 id + 别名表、`state.js` 增加 `migrateBuildingIds`——
方向正确；基线 config 仍是 `lumberyard/coalmine` 旧命名，P1-02 勾选以提交后为准。）

### 差距二：没有败局 = 没有 Frostpunk

民心跌穿 15、人口清零，目前只会打一条日志（UI 内核人口下限硬编码为 1）。生存游戏的一切可读性打磨（打磨线①②③）最终都服务于「我可能会输」的恐惧——地基不在，装修无义。systems 侧 `gameOver` 判定已实现，缺的只是接线 + 一个结算弹窗（ACCEPTANCE P0-13/14）。

### 差距三：有目标系统而无目标呈现

12 条任务链是现成的留存与教学骨架（打磨线⑩），一个任务托盘即可点亮，属于「一天工作量换体验档次跃升」的洼地。
