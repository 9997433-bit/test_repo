# SOTA.md — 对标基准与打磨线

> 作者：fable-accept（Round 1 补派）。本文回答一个问题：**这款致敬作离「一眼看上去就是好游戏」还差什么**。
> 对标三个坐标系：Frostpunk 的生存可读性、三国 SLG（率土/三战式）的养成反馈、以及通用 Juice（游戏手感）。
> 每条打磨线标注当前现状与验收锚点（对应 `ACCEPTANCE.md` 条目编号）。功能对错见 ACCEPTANCE，本文只管「好不好」。

---

## 1. 对标基准拆解

### 1.1 Frostpunk：生存压力必须**一屏可读**

Frostpunk 的核心不是数值难，而是玩家任何时刻扫一眼屏幕就知道三件事：
**现在多冷、还能撑多久、下一个坏消息什么时候来。** 落到本作：

| Frostpunk 要素 | 本作对应物 | 现状 |
|---|---|---|
| 温度计是世界的主角 | HUD 中央温度计（汞柱 + 档位文案 + 冻结变色） | ✅ 已有，缺「距冻结还差 N°」微文案与趋势箭头 |
| 热区可视（家家户户的温度圈） | 火炉暖光半径随等级扩大、熄火只剩青烟 | ✅ 光晕已随 level/lit 变化 |
| 倒计时式恐惧（风暴将至） | 天气条「N 日后寒潮」+ 寒潮横幅 + 全屏结霜 | ✅ 骨架齐全，缺寒潮**前夜**的升级紧迫感引导 |
| 资源余量换算成「还能活几天」 | 火炉面板「燃料可支 N 日」 | ✅ 有，但只在面板内，未常驻 HUD |
| 失败近在咫尺（不满/希望双表） | 民心条 + 崩溃线 15 | ❌ **民心跌穿只发日志，游戏不会输**——张力的地基缺失 |

### 1.2 三国 SLG：每一次投入都要有**即时、具体、可炫耀**的回报

率土/三战类的养成爽感三定律：抽卡要有仪式感、数值成长要可见（战力跳字）、克制要能被学会（战报教学）。

| SLG 要素 | 本作对应物 | 现状 |
|---|---|---|
| 抽卡开箱仪式 | 十连翻牌逐张入场（70ms stagger）、品质色框、保底紫 | ✅ 有基础版；缺橙/红将的全屏高光时刻 |
| 战力数字与羁绊 | 武将卡战力、同阵营 2/3 人 +8%/+18% 提示 | ✅ 有；羁绊只在文案，未做「即将凑齐」的诱导 |
| 克制教学 | 出征前胜算注记 + 战报「（克制）」标 | ✅ 有；缺乘区数值外显（+25% 写出来） |
| 养成多线（等级/星级/驻防） | UI 只有「重复=升级」单线；星级/碎片/驻防在 systems 侧睡觉 | 🟡 深度已写好，未上桌 |
| 目标牵引（任务链/成就） | 12 条主线任务链（数据+逻辑全有、单测通过） | ⬜ **无任何 UI 入口**，玩家感知不到目标 |

### 1.3 Juice：状态变化必须被「看到、听到、感到」

好手感 = 每个状态变化配一个 ≤600ms 的物理反馈。本作已有底子（升级建筑脉冲 `renderer.pulse`、toast、横幅、结霜遮罩、雪粒子三层、村民通勤），缺的是把反馈接到**每一个**关键事件上，并控制不过载。

## 2. 十二条打磨线

> 顺序即建议优先级。每条 = 目标 ／ 现状 ／ 差距动作 ／ 验收锚点。

**① 温度即命脉的一屏可读**
目标：不看数字也知道处境——温度计做主视觉，配「距冻结 N°」微文案与升/降趋势箭头，全局色调随温度带插值。
现状：温度计 + 档位文案 + 冻结变色已有；场景色调随寒潮变化已有。
差距：加趋势箭头与冻结差值；freeze 档位时 HUD 描边结霜（tokens.css 已备 `--border-frost` 类变量）。
锚点：P0-07。

**② 寒潮节拍的恐惧曲线**
目标：预警（前 1 天）→ 压迫（倒计时变红脉冲）→ 爆发（横幅+闪屏 0.5s）→ 释放（潮退日志+色调回暖），四拍齐全。
现状：倒计时、横幅、结霜、潮退日志齐；缺「倒计时 ≤1 天」的红色脉冲与潮退的视觉回暖瞬间。
差距：倒计时告警态；寒潮烈度逐场递增（systems 已实现）接入后，横幅需展示烈度让玩家感知螺旋升级。
锚点：P0-06、B-02。

**③ 燃料焦虑常驻化**
目标：「还能烧几天」是 Frostpunk 式核心焦虑，必须常驻 HUD 而非藏在面板里。
现状：dock 火炉按钮有「燃料 N 日」小字 + <2 日脉冲；面板内有完整数据。
差距：断供前 30s 级别的强提醒（toast + 温度计闪烁）；熄火瞬间给一次全屏暗场 0.3s——现在熄火只有日志，情绪价值为零。
锚点：P0-05。

**④ 资源流的因果可读**
目标：每个数字旁边都答得出「为什么在变」。净增/日已有，需补：悬浮资源出分解 tooltip（产出−口粮−燃料−练兵）、<1 天见底时下划线告警。
现状：净增/日、储量条、满仓/低量变色齐全；分解 tooltip 无。
差距：economy 系统的 `production/upkeep/perDay` 分解数据已算好（🟡 未接 UI），统一后直接喂 tooltip。
锚点：P0-11、P1-01。

**⑤ 升级的前因后果对照**
目标：所有升级按钮都能回答「花什么、得什么、为什么不能点」。
现状：now→next 产出对照、缺口资源标红、封顶原因文案——这块是当前 UI 最强的部分，保持。
差距：升火炉的「反向前置」（systems `furnacePrereqFor`：先把伐木场升到 N-1 才能升火炉 N）接入后，缺失前置要列清单，不能只说「不可升级」。
锚点：P0-08、P0-09。

**⑥ 派工的手感**
目标：加减工人像拨算盘：pip 点阵即时亮灭、产出数字同帧跳动、闲置丁口徽章同步。
现状：pip、闲置数、上限禁用全有。
差距：人口冻损导致的自动撤工目前无感知——需要一条「N 名工人冻伤离岗」toast + 建筑图标短暂变灰，否则玩家只觉得产量莫名下降。
锚点：P0-10、B-07。

**⑦ 招贤的仪式感升级**
目标：橙/红将出货 = 全屏时刻（绸带横幅 + 停顿 0.4s + 卡面高光扫过）；十连保底进度可视化。
现状：翻牌 stagger、品质色、重复转化文案已有；橙红将只多一条日志。
差距：出货高光；把「十连必出紫」写在按钮旁而非说明段落里；systems 的星级/碎片系统接入后，重复获得要有「星级 +1」的爆点动画。
锚点：P0-15。

**⑧ 战报的叙事与教学**
目标：战报是克制系统的教科书：每回合伤害数字外显克制乘区（「斩敌 1840（骑克弓 +25%）」）、胜负原因一句话总结。
现状：逐回合中文文案、克制标注、缴获/阵亡清单已有，质感不错。
差距：乘区数值化；接入 systems/combat 后回合是真实结算而非纯演出，技能触发事件（`rollSkills` 已产出事件流）要变成战报里的高光行。
锚点：P0-16、P0-17、P1-04。

**⑨ 养成反馈闭环**
目标：武将升级瞬间战力数字滚动上跳 + 卡面微弹；同阵营「差 1 人凑羁绊」的提示常驻招贤面板，驱动下一次抽卡。
现状：战力展示齐全，变化无动画；羁绊只有静态说明。
差距：数字滚动（UX.md 已规定 300ms 数字滚动规范，未实现）；「蜀 ×2，再得 1 名蜀将 +18%」这类临门一脚提示。
锚点：P0-15、P1-07。

**⑩ 任务链 = 隐形教程 + 目标牵引**
目标：屏幕上永远有一个「下一步该干嘛」——data/quests.js 的 12 条链就是为此设计的（奖励刻意前置：寒潮前推火炉 2 级并补煤）。
现状：逻辑与数据全部就绪且有单测，**玩家完全看不到**。
差距：一个侧边任务托盘（当前任务 + 进度条 + 领取红点）就能把留存曲线立起来；这是**性价比最高的一条线**。
锚点：P1-03。

**⑪ 微动效预算与节制**
目标：所有反馈 ≤600ms、警报闪烁 <3 次/秒且 3 次后转常亮（WCAG 2.3.1，UX.md 已立规）；toast 同类合并、最多 4 条。
现状：toast 上限 4 已实现；升级脉冲、横幅淡出节奏良好。
差距：全局盘点一次动效时长与频率，把「is-pulse」类告警统一到同一节拍器，避免多处各闪各的。
锚点：P0 全线的失败判定「表意红线」。

**⑫ 可读性与无障碍底线**
目标：正文对比度 ≥4.5:1；数字全部 tabular-nums 不横跳；品质/阵营用「颜色+文字」双通道（色弱可玩）；全部按钮键盘可达。
现状：品质双通道已达标（色 + 「精锐/史诗/传奇/绝世」文字）；阵营用单字徽记 ✅；对比度未审计；modal 无焦点陷阱。
差距：跑一次对比度审计（重点：`--text-faint` 系文字）；Esc 之外补 Tab 焦点环。
锚点：DESIGN §17 P0 最后两条。

## 3. 当前最大验收差距（按伤害排序）

### 差距一：双内核断层——引擎的「里子」和游戏的「面子」互不认识

这是压倒其余一切的结构性差距（详见 `ACCEPTANCE.md` §1.1）：

- 玩家玩到的是 `main.js` 里 850 行的应急内核：瞬发升级、标量兵力、`Math.random` 掷骰、永不失败；
- 而真正达到 SOTA 水准的系统——施工工期、三兵种确定性战斗、疾病/伤兵、任务链、星级养成、正规存档校验、可复现 RNG——全部躺在 `js/systems/*` 里**只被测试消费**。
- `npm test` 的那颗红灯（`quests/production` 门槛探针）就是这个断层的机读证据：探针拿扁平 state 问 `city.canUpgrade`，实现只认嵌套 state，谁也说服不了谁。

**后果**：游戏的深度上限被锁死在应急内核；且两套数值（抽卡概率、寒潮模型、火炉级数、开局资源共 3 套配置）会持续发散，越晚统一代价越大。
**收敛建议**：裁决嵌套 `state.js` 为唯一事实源；`main.js` 的 `view()` 改为从嵌套 state 派生的只读投影层，UI 面板全部改走 systems 的 action 函数。

### 差距二：没有败局 = 没有 Frostpunk

民心跌穿 15、人口清零，目前只会打一条日志（UI 内核人口下限硬编码为 1）。生存游戏的一切可读性打磨（打磨线①②③）最终都服务于「我可能会输」的恐惧——地基不在，装修无义。systems 侧 `gameOver` 判定已实现，缺的只是接线 + 一个结算弹窗（ACCEPTANCE P0-13/14）。

### 差距三：有目标系统而无目标呈现

12 条任务链是现成的留存与教学骨架（打磨线⑩），一个任务托盘即可点亮，属于「一天工作量换体验档次跃升」的洼地。

## 4. 优先级建议（给下一轮排期）

1. **P0 修断层**：状态树统一 + 测试转绿（差距一）——其余打磨在此之上才不白做。
2. **P0 立张力**：败局/结局 + 结算弹窗（差距二）。
3. **P1 点目标**：任务托盘（差距三，打磨线⑩）。
4. **P1 提手感**：打磨线①②③⑦⑧（温度/寒潮/燃料/抽卡/战报——五条决定第一印象）。
5. **P2 补氛围**：打磨线⑨⑪⑫ 与音频、事件抉择。
